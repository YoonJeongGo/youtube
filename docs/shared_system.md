3. 새 대결은 전제와 전체 대본 확인이 먼저다. 그림 판단은 Codex가 맡는다. 승인 전 생성이나 영상 합성을 검사 명목으로 시작하지 않는다.
4. `queue.txt`, `done.txt`, `state/project_state.json`, `episodes/`를 확인하고 기존 작업 ID/폴더를 재개한다. 같은 대진의 순서를 바꿔 중복 제작하지 않는다.

## 규칙이 바뀌면

- 사용자가 전역 규칙으로 지정한 내용은 해당 상세 문서와 `docs/decision_log.md`를 함께 갱신한다. 한 편의 수정이나 예외는 그 편의 승인 기록에 둔다.
- 원문 지시, 적용 범위, 날짜, 바뀐 문서와 남은 미확인을 짧게 남긴다. 불명확한 제작 기준을 임의로 확정하지 않는다.
- 다른 채팅이 같은 작업 폴더를 사용하면 파일은 공유되지만, 이미 진행 중인 대화가 변경을 즉시 읽었다고 보장하지 않는다. 사용자 승인 범위에서 갱신 안내를 전달하고 실제 읽음/응답 여부를 구분한다.
- 작업 중인 파일은 덮어쓰지 않는다. 동시 변경이 보이면 현재 해시와 변경 내용을 다시 확인한 뒤 반영한다.

## 보존과 GitHub 구조

- 저장소에는 제작 코드, 의존성 목록, 테스트, 규칙과 설명을 둔다. `.venv`, 모델 가중치, 캐시, 인증정보, 전체 채팅 기록은 올리지 않는다.
- `archives/`는 영상 ZIP의 목록·제목·검수 상태·크기·SHA-256·다운로드 링크를 둔다. 실제 큰 ZIP은 GitHub Releases 첨부로 보관한다. 일반 소스 checkout을 받을 때 미디어가 함께 내려오지 않게 한다.
- `README.md`는 설치/실행 안내, 상세 제작 문서는 규칙의 기준, `archives/catalog.json`은 원격 보관 목록이다. 원격 보관 성공이 영상 품질 PASS나 유튜브 게시를 뜻하지 않는다.
- 업로드 전 파일 목록과 민감정보를 확인하고, 업로드 후 원격 크기·해시 또는 다시 읽은 바이트 해시를 대조한다. 새 확인 없이 로컬 원본·완성본·진행 중 자료를 지우지 않는다.
- F 드라이브의 기존 ZIP은 과거 보관본일 수 있다. 현재 작업본과 해시가 다르면 둘을 최신본으로 혼동하지 않고 버전과 누락 범위를 기록한다.

## 현재 확인 범위

- 2026-11-18 현재 이 프로젝트의 네 채팅은 같은 작업 폴더를 사용한다. 다른 프로젝트의 채팅이나 향후 별도 checkout까지 자동 동기화됐다고 주장하지 않는다.
- 같은 날 쇼츠 생성 방 1·2·3과 대결 쇼츠 제작 규칙 숙지 방에서 공통 규칙의 실제 읽음을 확인했다. 이는 해당 시점의 확인이며, 이후 변경은 다시 읽는 절차를 따른다.
- 현재 기본 TTS는 기존 인준 설정이다. 별도 OpenVoice 실험은 그 작업의 승인 범위이며, 설치만으로 기본 화자나 전체 프로젝트 설정을 바꾸지 않는다.
- Gemini는 금지다. 실제 청취와 ASR/파형/신호 검사는 구분하며 미확인 음향을 PASS로 올리지 않는다.
- 제목은 `<영상 제목> #가상대결 #쇼츠 #A인물 #B인물`, 전달 폴더도 전체 제목과 같다. 원본/실제 MP4 썸네일 이름 크롭과 작은 목록 미리보기를 각각 확인한다.

이 요약과 세부 기준이 충돌하면 최신 사용자의 명시적 지시와 해당 프로필의 상세 규칙을 확인한다. 과거 v4 호환 절을 신규 v5 규칙으로 다시 적용하지 않는다.
