## 검토 기록을 남기는 방법

- 기존 기획 검토 문서, `storyboard.json`, `qa_report.md`와 해당 버전의 대본·출처 기록을 사용한다. 이 검수표를 위해 편별 새 필수 파일·episode schema·검수 서비스는 추가하지 않는다.
- 각 항목에 실제로 읽은 대본의 씬/컷/cue 또는 문장, 관찰한 행동·인과·문제, 수정 내용과 남은 문제를 적는다. 형식이 있다는 이유로 내용 확인을 대신하지 않는다.
- 표는 빈 검토 양식이다. 실제 확인 전 결과를 `PASS`로 미리 채우지 않는다. 확인·수정 필요·미검토·해당 없음과 이유를 서술하되 새 기계 상태값을 강제하지 않는다.
- 대본·주요 전제의 제작 승인과 내용 검토, 생성 자산 검사, 최종 사용자 청취 승인은 각각 구분한다. 체크리스트 작성이 사용자 승인을 대신하지 않는다.
- `check_episode.py --text-only`의 구조 검사나 시간 합산 성공은 재미·인과·원전 타당성·공방 충실도의 자동 PASS가 아니다. `kind: clash` 같은 분류명만 보고 전투 구간으로 단정하지 않는다.

| 장면·그림 연결 | 대본의 실제 행동에 맞는 대표 순간과 구도인가? 얼굴 노출을 위해 몸을 비틀지 않는가? | 행동 주체·손/무기 소유·지지 자세·카메라·가림, 앞뒤 컷 연결, 신규/수정/재사용 이유. 아직 미생성 이미지는 계획 검토만 했다고 명시. |
| 서사 고유성 | 특정 의뢰·오해·공동의 적·동맹·탈출·귀환을 기본 공식으로 반복하지 않는가? | 비교한 기존 사건과 갈등·목표·전술·선택·해결 방식의 실제 차이. |

관찰 없는 일괄 체크, 자동 검색어 결과, 자체 점수만으로 위 항목을 통과시키지 않는다. 직접 대사가 많거나 세부 묘사가 길다는 사실 자체도 재미와 사건 진행의 증거가 아니다.

## 시간과 전투 구간 검토

### 기획 단계

- 전체는 도입·본문·결말·질문·댓글 안내·전환을 포함해 최종 9~15분을 목표로 설계한다. 예상값은 낭독 분량·발화 속도 가정·장면 구성에 따른 추정임을 밝힌다. 고정 글자 수를 정답으로 삼지 않는다.
- 전투 약 3분은 완성 영상에서 공방이 진행되는 시간의 기본 목표다. 이야기 속 시간과 다르며 정확히 180초를 강제하거나 새 합격 허용범위를 만들지 않는다.
- 대본을 실제로 읽고 전투의 시작·종료를 지정한다. 공격·방어·회피·견제·유인·거리/위치 조절과 연결된 짧은 전술 판단·결과 설명은 포함할 수 있다. 긴 원전 회상·관계 해명·반복 설명·동일 공방의 도입 재탕으로 부풀리지 않는다.
- 조준·바라보기 설명을 늘리거나 같은 공격/회피를 재탕해 목표를 채웠는지 확인한다. 전투 횟수·비율·이미지 수로 품질을 대신 평가하지 않는다.
- 여러 전투 구간은 시작·종료와 합계를 기록하고 겹치는 시간은 한 번만 센다. 반복해서 보여준 같은 공방과 제외한 구간은 그 이유를 명시한다.

기존 기획 시간표/검토 문서에 다음 정보를 연결한다. 아래 표를 위해 별도 편별 파일을 강제하지 않는다.

| 단계·버전 | 전투 구간 시작·종료 식별자 | 시작 시각 | 종료 시각 | 길이 | 포함한 공방과 판단 근거 | 제외 구간·중복 처리 |
|---|---|---|---|---|---|---|
| 기획 추정 | 실제 대본 기준 | 미산정 | 미산정 | 미산정 | 실제 관찰·계획 | 해당 시 기록 |
| 생성 음성 시간표 | 실제 cue/프레임 기준 | 미측정 | 미측정 | 미측정 | 대본과 시간표 대조 | 해당 시 기록 |
| 최종 영상 실측 | 현재 MP4와 시간표 기준 | 미검수 | 미검수 | 미검수 | 실제 영상의 공방 내용 | 해당 시 기록 |

전체 예상 길이와 전투 예상 합계를 함께 쓰되, 미측정 칸을 0초나 실측 PASS로 바꾸지 않는다. 약 3분과 차이가 나면 필요한 대응이 빠졌는지·불필요한 연장이 있는지·한쪽 능력을 억지로 제한했는지 실제 내용을 검토한다. 이야기가 목표 분량에 성립하지 않으면 원인을 해결한 재구성/근거 있는 대안을 먼저 제시한다.

### 음성·편집 이후 재측정

- 기존 `timeline.json`의 실제 cue 시작·끝 프레임/시간과 최종 MP4의 재생시간을 사용한다. 추정, 생성 음성 시간표 실측, 최종 MP4 실측을 같은 값인 것처럼 섞지 않는다.
- 지정 구간의 시작 cue부터 종료 cue까지는 해당 cue를 포함하는 구간이다. 경계와 실제 공방 내용이 맞는지 사람이 읽고 확인한다. 경계가 cue 중간이면 현재 도구의 정밀도 한계를 밝히고 필요한 대본/편집 경계를 조정한다.
- 공방 중간의 긴 회상이나 반복 훅이 있으면 이를 제외하는 구간으로 나누어 합산한다. 겹치는 구간은 합집합으로 한 번만 합산하고, 같은 공방의 재탕을 별개 전투처럼 더하지 않는다.
- 최종 전체 540~900초는 유지해야 하는 범위다. 전투 합계 약 180초는 내용 검토와 함께 보는 기본 목표이며 수치만으로 합격/불합격시키지 않는다.
- 최종 영상이 없으면 최종 영상 길이·전투 검수는 미실시다. 시간표가 없으면 전투 실측을 만들지 않는다. 오래된 대본/시간표/영상의 값을 현재 버전 실측처럼 재사용하지 않는다.
- 부족하거나 넘친 원인을 확인해 대본·편집을 조정한다. 반복 설명·정지 화면·긴 무음으로 형식적인 길이를 맞추지 않는다.

### 현재 도구와 연결

다음은 기존 기록을 읽는 검토 보조 명령이다. 실제 에피소드 경로와 검토자가 내용으로 판단한 구간을 사용한다.

```powershell
.\run_python.ps1 plan_matchups.py longform-guidance
.\run_python.ps1 check_episode.py $longformEpisode --text-only

# combatCueRange는 실제 시작cueID:종료cueID 문자열이며 두 cue를 모두 포함한다.
.\run_python.ps1 check_episode.py $longformEpisode --longform-timing-report --combat-range $combatCueRange
```

- 여러 구간은 `--combat-range`를 반복한다. 중간의 긴 회상·도입 재탕을 제외할 구간은 실제 내용을 읽고 나눠 지정한다. 겹침은 한 번만 합산한다.
- 구간을 지정하지 않으면 전투 합계는 미분류/null이다. 0초나 목표 미달 판정으로 해석하지 않는다. 도구가 `kind`나 인물 이름으로 공방을 자동 분류한다고 여기지 않는다.
- 계획 길이, 기존 시간표의 전체·구간 길이, 최종 MP4가 있을 때의 실제 전체 길이와 근거 경로·해시를 구분해 읽는다. 없는 파일의 실측을 만들어내지 않는다.
- 시간 보고 명령은 품질 검수나 사용자 승인 기록을 만들지 않는다. 180초와의 숫자 차이만으로 내용 PASS/FAIL을 기록하지 않고 위 검수표의 실제 관찰과 함께 판단한다.

## 검토 결론과 다음 단계

기존 검토 기록에 실제 확인한 범위, 발견한 문제와 해당 씬/문장, 수정 내용, 남은 문제, 전체·전투 예상 또는 실측 길이의 근거를 남긴다. 필요한 검토가 남으면 그 한계를 명확히 쓰며 도구 성공을 내용 PASS로 바꾸지 않는다. 기존 `qa_signoffs.json`의 현재 script/출처 연결은 실제 검토가 끝난 그 버전에만 갱신한다.

전체 대본·전제·예상 시간·공방표·이미지 연결표를 먼저 제시하고 해당 변경 범위의 제작 승인을 확인한다. 유효한 같은 범위 승인을 다시 요구하지 않는다. 승인 후 이미지 전체 초안→실제 등장 순서 이미지 전용 검토→피드백 수정·재검수→음성·자막·편집→최종 검수 순서를 유지한다.

이미지의 손·팔·관절·지지·무기·가림 오류는 [공통 이미지 기준](image_geometry_rules.md)에 따라 실제 전체·세부 보기를 열어 확인하고 수정 후 다시 본다. 프롬프트에 지시했다는 이유만으로 이미지 검수를 통과시키지 않는다.

최종 영상에는 실제 전체 길이·전투 구간과 합계·수정한 문제·남은 문제를 보고한다. ASR 대본 대조·누락·끝 잘림·음량·자막 동기 기술 검사와 최종 MP4 전체 사용자 청취 승인을 구분한다. 사용자가 전체 영상을 끝까지 듣고 승인하기 전 최종 음성 PASS는 기록하지 않고 `청취 승인 대기`로 보고한다.
