## 2026-11-20 추가: 다음 롱폼의 노림·근접 공방

[최신 사용자 요청 원문](requests/2026-11-20-longform-intent-close-combat-request.txt)을 **이 요청 이후 새로 기획하는 롱폼**에 적용한다. 현재 승인된 ‘척준경 VS 미야모토 무사시 — 방패 뒤에서 두 번째 소리가 났다’의 대본·음성·컷 순서를 소급 변경하지 않는다. 현재 편의 B안 그림 수정과 반달·자막·음량 수정은 해당 편의 별도 승인 범위다. 아래 이전 규칙과 충돌하는 경우 이 추가 기준이 우선한다.

### 이야기의 노림과 대가

- 의도·수단을 숨겼다가 뒤늦게 밝혀 긴장을 만드는 서사 장치는 **한 편에 최대 한 번**만 쓴다. 나머지 공방은 공격 또는 대응의 결과가 나오기 전에 **무엇을 노리는지 먼저 보여 준다**. 의도 공개와 승패·결말 선공개를 혼동하지 않는다.
- 공방마다 **‘노림 → 막음이나 실패 → 대가’**를 한 줄로 적고 실제 낭독·그림에 연결한다. 무엇을 보고 판단했는지, 왜 막혔거나 실패했는지, 그 때문에 거리·자세·주도권·목표 상태·위험이 어떻게 달라졌는지 구체적으로 쓴다. 기존 ‘행동 → 상대 변화 → 대응 → 새로운 상황 → 다음 판단’의 인과를 유지한다.
- **전체 공방의 절반 이상에서 승리 조건이 한 뼘 차이로 위협받게 한다.** 노리는 목표, 바로 성공하거나 실패할 수 있었던 순간, 이를 막은 행동, 남은 대가를 확인한다. 단지 칼이 가까이 보인다는 이유로 충족 처리하지 않는다. 원전 능력·한계를 바꾸거나 근거 없는 간파·필중·새 약점을 붙여 위기를 만들지 않는다.
- **첫 공방은 최종 영상 시작 후 3분 안에 시작한다.** 본 사건에서 행동과 상대 대응으로 상황이 실제 바뀌는 첫 공방을 뜻한다. 도입에서 미래의 공방을 잠깐 재생한 것만으로 충족 처리하지 않는다. 기획에서는 예상 시작, 음성·최종 영상에서는 실제 시작을 기록한다.
- 전체 **9~15분(540~900초)**, 전투 합계 약 3분의 기존 기본 목표는 유지한다. ‘공방의 절반 이상’은 이번에 사용자가 지정한 위협 장면의 구성 기준이며, 기존에 금지한 임의의 고정 전투 시간 비율·공방 수·이미지 수와 다르다. 시간이나 비율만 맞춘 반복 공격·긴 정지·해설은 넣지 않는다.

### 그림의 근접 공방

구도·거리·중복 확인의 상세 기준은 [전투 컷 연출의 최신 추가 기준](longform_combat_direction.md)을 따른다. 두 사람 전신 측면은 공방당 최대 한 장, 나머지는 한 사람/눈·손·발·칼끝의 근접과 극단 원근을 사용한다. 접촉하는 공방의 두 사람은 팔 하나 이내 거리로 붙이고, 같은 전투 구도를 한 편에 두 번 쓰지 않는다. 인체 정확성을 지키기 위해 두 사람을 멀리 떨어뜨리는 방식을 기본 해법으로 삼지 않는다.

기존 인준 음성·낭독 호흡·자막/화면 기본값과 사용자 최종 청취 승인 절차, 쇼츠 시스템은 유지한다. 아래 [기획 프롬프트](longform_planning_prompt.md)와 [대본 검수표](longform_script_review.md)에 실제 노림·대가·시각 근거·시작 시각을 남긴다. 문서 갱신이 현재 영상 수정이나 미디어 검수 완료를 의미하지 않는다.

2026-11-19 개정. 적용 형식은 `longform`, 제작 프로필은 기존 `showdown_story_long_v1`이다. [최신 사용자 요청 10절](requests/2026-11-19-longform-story-system-request.txt)을 아래 현재 운영 기준에 통합했다. 특정 인물·대진·질문·줄거리·첫 작품을 기본값으로 두지 않는다.

## 현재 추가 기준: 낭독 호흡과 화면 전환 (2026-11-19)

### 낭독의 기본 호흡

| 경계 | 기본 쉼 |
|---|---|
| 문장 사이 | 0.3~0.5초 범위, 운영 기본값 0.4초 |
| 같은 장 안의 문단 사이 | 0.7초 |
| 장이 바뀌는 경계 | 1.2초 |

- 같은 경계가 문장·문단·장 전환에 동시에 해당하면 해당하는 가장 큰 단위의 쉼 하나를 적용한다. 값을 합산하지 않는다.
- 자막 cue나 그림 컷이 나뉘었다는 이유만으로 문장 중간에 새 쉼을 넣지 않는다. 대본의 문장·문단·장 경계와 실제 생성 음성의 끝을 기준으로 호흡을 맞춘다.
- TTS 자체의 앞뒤 무음에 편집 무음을 중복해서 더해 쉼이 길어지지 않게 실제 음성으로 확인한다. 예상 길이와 실측 길이를 구분하며, 사용자의 무음 비중 진단을 측정 결과로 전재하지 않는다.
- 신규 롱폼의 실제 적용 조건과 정책 파일·실행 명령·파형 보호·원본 재구성 검증은 [롱폼 음성 호흡 편집 실행](longform_voice_pacing.md)을 따른다. 공통 문장 기본값은 모든 장 0.4초이며, 이번 B안의 앞 7장 0.3초는 편별 조건이다.

### 화면 유지와 대화 컷

- **같은 그림의 동일 정지 구도는 비전투 20초 이내, 전투 8초 이내로 유지한다.** 전투는 [전투 컷 연출 13절](longform_combat_direction.md)에 따라 새 정보에 맞는 크롭·연결 컷으로 나눈다. 자막 문장만 바뀐 것은 새 구도로 계산하지 않는다.
- 대화 장면은 **현재 말하는 인물 쪽 컷으로 전환**한다. 상대의 말을 길게 듣는 동안 같은 넓은 대화 그림을 고정하지 않는다.
- 먼저 기존 그림에서 **얼굴·손·소품의 확대 크롭**으로 필요한 컷을 구성한다. 다른 세부를 보여 주는 컷으로 의미 있게 전환하고, 기존 그림과 크롭으로 부족한 컷만 새로 생성한다.
- 크롭에서도 인물의 손·팔·무기와 소품의 핵심 접점, 화면 방향과 사건 연결이 읽혀야 한다. 기존 원본을 보존하고 실제 사용 화면을 확인한다.
- 호흡과 컷을 바꿔도 공통 전체 영상 기준은 **9~15분(540~900초)**으로 유지한다. 시간을 채우려고 쉼이나 같은 정지 구도를 늘리지 않는다.

## 현재 1. 전체 방향과 길이

- 롱폼은 도입·본문·결말·댓글 안내·전환을 포함해 실제 완성 영상 기준 9~15분으로 만든다.
- 시청자가 초반에는 인물과 상황을 궁금해하고, 중반에는 사건의 진행과 선택을 따라가며, 전투에서는 능력과 전술의 충돌을 보고, 마지막에는 그 결과를 확인하게 구성한다.
- 전투 장면은 완성 영상에서 약 3분을 기본 목표로 한다. 정확히 180초를 맞추려고 동작을 늘이거나 필요한 공방을 자르지는 않는다.

- 전투 외의 시간에도 사건이 진행되어야 한다. 인물 소개와 전투 사이를 긴 해설로 채우지 않는다.
- 전투 비율이나 공방 횟수, 이미지 수를 모든 편에 동일하게 고정하지 않는다.

## 현재 2. 인물을 이해시킨 뒤 그 인물의 이야기로 들어간다

기본 흐름은 다음과 같이 잡는다.

도입 → A·B 이해 → 한 인물의 진행 중인 행동을 따라가는 이야기 → 사건 발단 → 갈등의 전개 → 위기 → 결정적 충돌과 절정 → 결말·질문

- 도입은 약 30초 안에 사건의 긴장이나 핵심 질문을 제시한다. 승패와 결말을 처음부터 설명하지 않는다.
- A와 B의 배경·성격·가치관·능력·한계·원전 활약을 이번 사건에 필요한 만큼 소개한다.
- 능력 목록을 읽는 데 그치지 말고, 실제 활약을 통해 어떤 인물이며 어떻게 행동하는지를 이해시킨다.
- 인물 소개가 끝나면 A 또는 B가 이미 진행하고 있던 일이나 추구하던 목표를 따라가며 본격적인 이야기로 들어간다.
- 필요하면 상대편의 행동을 교차해 보여줄 수 있지만, 같은 상황을 양쪽 관점으로 길게 반복하지 않는다.
- 추가 정보는 필요한 행동 직전이나 사건 중간에 짧게 넣을 수 있다. 이미 소개한 내용을 다시 장황하게 설명하지 않는다.

## 현재 3. 초반부터 구체적인 장면으로 사건을 진행한다

‘두 사람이 만났다’, ‘서로 오해했다’, ‘싸움이 시작됐다’라는 요약만으로 중요한 과정을 넘기지 않는다.

- 인물이 지금 어디에서 무엇을 하고 있는가.
- 무엇을 얻거나 지키려 하는가.
- 주변에서 어떤 변화가 발생하는가.
- 인물은 무엇을 보고 듣고 알아차리는가.
- 그 정보를 어떻게 해석하고 무엇을 선택하는가.
- 그 선택에 따라 실제로 무엇을 하거나 말하는가.
- 상대는 무엇을 알고 어떤 반응을 보이는가.
- 그 결과 어떤 새로운 상황이나 문제가 생기는가.

이 항목을 문장 틀처럼 매번 반복하지 말고, 자연스럽게 이어지는 장면으로 작성해.

- 위치, 거리, 시선, 소리, 물건, 몸의 움직임은 인물의 판단과 다음 행동에 필요한 만큼 구체적으로 묘사한다.
- 등장인물의 말을 모두 간접 설명으로 처리하지 말고, 필요한 순간에는 실제 대사를 사용한다.
- 대사는 인물의 성격·목표·의심·정보에 맞아야 하고, 말한 뒤 행동이나 관계에 변화가 생겨야 한다.
- 나레이션은 장면을 이해하도록 돕는다. 화면에서 충분히 보이는 행동을 같은 뜻으로 반복 설명하지 않는다.
- 풍경이나 생활 동작도 사건과 관련이 있어야 한다. 세부 묘사를 늘리는 것 자체를 재미로 간주하지 않는다.
- 장면이 끝났을 때는 정보·관계·위험·목표의 상태·선택 중 적어도 하나가 의미 있게 달라져야 한다.

## 현재 4. 발단·전개·위기·절정·결말의 역할

① 발단
인물이 하던 일과 상대의 행동이 연결되면서 중심 사건이 발생한다. 각자의 목표와 충돌 이유가 행동과 대사에서 드러나야 한다. 두 인물을 싸우게 하려고 성격에 맞지 않는 행동을 시키지 않는다.

② 전개
발단에서 발생한 문제에 대응하면서 갈등이 발전한다. 관찰·대화·접근·견제·첫 충돌 등 앞선 선택의 결과가 다음 선택을 만들어야 한다. 말로 해결할 수 있는 상황에서 무력 충돌이 일어난다면, 왜 대화로 해결되지 않았는지도 납득시킨다.

③ 위기
앞선 행동 때문에 계획이 어긋나거나, 목표 달성이 어려워지거나, 선택의 대가와 위험이 커진다. 갑자기 등장한 새 약점이나 능력 제한으로 위기를 만들지 않는다. 양쪽을 반드시 번갈아 불리하게 만들 필요는 없다.

④ 절정
앞에서 보여준 능력·성격·판단·위치·단서가 결정적인 충돌에서 결과를 만든다. 앞선 공방이 이 순간에 영향을 줘야 한다. 갑자기 추가된 능력이나 제3자의 개입으로 중심 갈등을 대신 해결하지 않는다.

⑤ 결말
처음 제시한 중심 사건과 승부 목표가 어떻게 끝났는지 보여준다. 누가 무엇을 얻고 잃었는지, 선택의 결과가 무엇인지 명확하게 마무리한다.

다섯 단계를 같은 길이로 나누거나 독립된 챕터로 억지 구분하지 않는다. 전투는 전개·위기·절정에 걸쳐 자연스럽게 이어질 수 있다.

## 현재 5. 약 3분의 전투를 구성하는 기준

- 전투 시간은 이야기 속에서 흐른 시간이 아니라, 완성 영상에서 공방이 전개되는 구간의 길이를 뜻한다.
- 공격·방어·회피·견제·유인·거리 조절·위치 변경 등이 서로의 선택과 상황에 영향을 주며 이어져야 한다.
- 공방의 기본 구조는 ‘행동 → 상대에게 생긴 변화 → 대응 → 새로운 상황 → 다음 판단’이다.
- 무엇을 보고 판단했는지, 무엇을 시도했는지, 왜 성공하거나 실패했는지를 이해할 수 있게 보여준다.
- 같은 공격과 회피를 반복하지 않는다. 첫 시도 이후에는 얻은 정보, 거리, 위치, 목표 상태, 위험 등이 다음 행동에 영향을 줘야 한다.
- 조준하거나 바라보는 동작의 설명만 길게 늘려 전투를 충분히 구성했다고 판단하지 않는다.
- 짧은 전술 판단과 공격 결과 설명은 해당 공방에 연결해 사용할 수 있다. 긴 원전 회상이나 반복 해설로 전투 분량을 부풀리지 않는다.
- 도입에서 보여준 동일한 공방을 본문에서 반복하는 시간을 이용해 전투 목표를 채우지 않는다.
- 한쪽이 계속 우세한 전개도 가능하다. 양쪽에 성공과 실패를 기계적으로 한 번씩 배분하거나, 반드시 역전극으로 만들지 않는다.
- 전투가 끝나는 이유와 마지막 공방이 결과에 미친 영향을 분명히 보여준다.

## 현재 6. 원전과 창작의 경계

- 인물의 정체·성격·능력·무기·한계는 선택한 원전과 판본의 근거를 지킨다.
- 서로 다른 판본의 유리한 능력을 임의로 합치지 않는다.
- 만남·장소·목표·대사·전술·사건 진행·승부 결과는 가상 이야기로 구성할 수 있다. 원전의 사실과 이번 창작을 구분한다.
- 강한 능력을 갑자기 없애거나, 사용 횟수·준비시간·새 약점·상대의 간파 능력을 만들어 전투를 늘리지 않는다.
- 강한 능력을 사용하지 않는 선택이 필요하다면, 그 이유가 인물의 목표·가치관·상황에서 자연스럽게 나오도록 앞에서 보여준다.
- 유리한 능력을 쓰면 해결되는 상황에서 아무 이유 없이 사용하지 않게 만들지 않는다.
- 인물의 능력과 성격을 지키면서 목표 분량의 서사가 성립하는지 기획 단계에서 검토한다. 성립하지 않는 안은 설명을 늘려 제작에 넘기지 말고, 문제를 해결한 기획이나 근거 있는 대안을 제시한다.

## 현재 7. 결말의 분위기는 고정하지 않는다

- 해피엔딩, 화해, 교훈적인 마무리를 의무로 두지 않는다.
- 승리·패배·부분적인 성공·손실·희생·비극·씁쓸한 결과 등 사건과 선택에 맞는 결말을 사용할 수 있다.
- 좋은 결말이나 나쁜 결말을 미리 정해 놓고 그 감정을 만들려고 인물의 능력과 성격을 뒤틀지 않는다.
- 전투에서 이겼다는 사실과 인물이 원하던 것을 얻었다는 사실은 다를 수 있다. 그런 차이가 있다면 사건 안에서 납득시킨다.
- 여운을 남길 수는 있지만, 중심 사건의 결과를 댓글이나 다음 편으로 떠넘기지 않는다.
- 후일담은 결과를 이해하는 데 필요한 만큼만 사용한다. 이미 보여준 승패와 선택을 여러 번 해명하지 않는다.
- 마지막에는 실제로 보여준 선택이나 결과에 관한 질문을 하고, “여러분의 생각을 댓글로 남겨 주세요.”를 한 번 읽는다.

## 현재 8. 그림과 장면 연결

- 전투 컷은 [전투 컷 연출·프롬프트·편집 기준](longform_combat_direction.md)의 01~16을 함께 적용한다. 박자별 대표 순간, 실제 영문 입력 9개 칸과 참조·BASE/ACTION LOCK, 소재별 효과, 정보 공개, 30fps 편집과 원본/360px 검수의 상세값은 그 문서 한 곳에서 관리한다.
- 대본의 행동을 먼저 정하고, 그 행동이 자연스럽게 보이는 카메라 각도를 선택한다.
- 정면 얼굴을 고집하지 않는다. 측면·뒷모습·사선·어깨너머 시점 등을 자유롭게 사용한다.
- 얼굴을 보여주려고 목·허리·골반·팔다리를 부자연스럽게 비틀지 않는다.
- 복장·체형·머리 모양·무기·장비의 일관성을 유지한다. 의도적으로 상태가 변했다면 이후 컷에도 그 변화를 연결한다.
- 손의 주인과 손목·팔꿈치·어깨의 연결, 다리와 관절, 무게중심, 물건을 잡거나 받치는 자세를 실제 이미지에서 확인한다.
- 무기는 끝에서 끝까지 형태를 추적한다. 손 앞뒤에서 창대나 칼이 갑자기 꺾이거나, 어긋나거나, 신체와 뒤섞이는 오류를 수정한다.
- 자연스럽게 가려진 부위를 억지로 드러내지 않되, 보이는 부분을 연결했을 때 인체와 물체의 구조가 성립해야 한다.
- 장소·이동 경로·인물 간 위치·공격 방향·가림 관계를 미리 정하고 컷 사이에서 유지한다.
- 이미지 수는 장면과 동작의 변화에 맞춰 정한다. 한 그림을 오래 유지해 분량을 맞추지 않는다.

## 현재 9. 제작자가 먼저 완성할 기획과 검토 자료

사용자에게 세부 설정을 하나씩 정해 달라고 넘기지 말고, 다음 내용을 갖춘 검토안을 먼저 완성해.

- 중심 사건과 핵심 질문.
- A·B의 목표, 행동 동기, 각자가 아는 정보와 성공 조건.
- 소개 이후 누구의 행동을 따라 이야기로 들어갈지.
- 사건 발단부터 결말까지 이어지는 선택과 결과.
- 장소·이동 경로·능력·제약.
- 전체 낭독 대본.
- 씬별 사건 변화와 예상 시간.
- 전투 구간의 시작·종료·예상 합계 시간.
- 공방별 행동·상대 대응·실제 결과.
- 이미지 연결표와 예상 제작량.
- 원전 근거와 창작 부분의 구분.

예상 시간과 실제 생성한 음성의 측정값을 구분해. 아직 생성하거나 검수하지 않은 자산을 완료 또는 PASS로 보고하지 마.

## 현재 10. 승인 이후 제작과 최종 검수

전체 대본·전제·예상 시간·공방표·이미지 연결표 제시 → 사용자 승인 → 이미지 전체 초안 생성 → 등장 순서대로 실제 이미지 검토 → 피드백 반영과 수정·재검수 → 음성·자막·편집 → 최종 영상 검수 순서로 진행해.

- 승인된 범위의 개별 이미지 수정마다 다시 승인을 반복 요청하지 않는다.
- 그림은 원본 확대와 가로 360px 미리보기를 실제로 열어 확인하고, 신체·무기·동작·공간 연결 오류를 고친 뒤 다시 검수한다. 전투는 그림만으로 먼저 이어 본 뒤 실제 음성과 함께 접촉 전후·공개 순서·효과음의 접촉 프레임을 확인한다.
- 실제 생성 음성에 맞춰 편집하고, 최종 영상의 전체 길이가 9~15분인지와 전투 구간이 약 3분으로 구성됐는지 확인한다.
- 길이가 맞지 않으면 원인을 확인하고 대본과 편집을 조정한다. 반복 설명과 정지 화면을 추가해 형식적으로 맞추지 않는다.
- 음성은 자동 전사와 대본의 대조, 누락, 끝 잘림, 음량, 자막 동기 등을 기술 검사한다.
- 최종 음성 PASS는 사용자가 전체 영상을 끝까지 듣고 승인한 뒤 확정한다. 그전에는 기술 검사 결과와 함께 ‘청취 승인 대기’로 보고한다.
- 최종 결과물과 함께 실제 전체 길이, 전투 구간과 합계 길이, 수정한 문제, 남아 있는 문제를 보고한다.

이 기준을 반영한 뒤에는 기존의 ‘사건을 요약하고 짧게 싸운 다음 길게 설명하는 방식’에서 벗어나, 인물의 구체적인 행동과 선택이 발단부터 결말까지 이어지는 롱폼을 제작해.

## 현재 기준의 제작·자산 연결

- 이미지 제작은 현재 10절 순서를 따른다. 전체 대본·전제와 시간·공방·이미지 계획 승인 뒤 전체 이미지 초안을 먼저 완성하고, 본편은 **실제 재생 순서대로 01부터** 나열한다. 파일명·씬 ID 정렬로 순서를 대신하지 않으며 썸네일은 본편 순번과 분리한다. 원본과 큰 그림으로 확인할 검토 자료를 함께 제공한다.
- 이 첫 전달은 이미지 전용 검토다. 개별 그림의 심층 자동 수정 반복으로 전체 초안 전달을 미루거나 음성·완성 영상 청취를 같은 단계에 요구하지 않는다. 초안 생성 완료와 이미지 품질 PASS를 구분한다. 사용자 피드백과 사용 예정 컷의 명확한 오류를 승인된 범위·기존 수정 한도에서 수정하고 실제 재검수한 뒤 음성·자막·편집 단계로 간다. 컷별 재승인을 반복 요구하지 않는다.
- [공통 이미지 생성·검수 기준](image_geometry_rules.md)의 `action_anatomy_continuity_v1`을 신규 그림과 사용 예정인 기존 그림에 함께 적용한다. 전체·필요 세부를 실제로 열어 손의 소유, 손→손목→팔꿈치→어깨, 골반→무릎→발목, 손 앞뒤 무기 축·두께·위치, 그립·지지, 몸통 앞뒤, 문·기둥·인물의 가림 관계를 확인한다. 얼굴 정면보다 동작과 공간이 자연스러운 시점을 선택한다.
- 정상적인 가림을 억지로 펼치지 않되 보이는 구조가 성립해야 한다. 오류 수정 후 문제 부위·원본 전체·주변 접점·영향받은 컷을 다시 확인한다. 미열람·미해결 상태, 기존 수정 횟수와 해시를 숨기거나 초기화하지 않는다. 사용자 청취 승인은 이미지 오류의 면제가 아니다.
- 기존 대본·그림·음성·시간표·승인·검수·수정 이력은 보존한다. 재구성안의 이미지 연결표에 자산별 재사용·수정·새 제작과 이유를 기록한다. 이미 유효한 자산은 이유 없이 재생성하지 않으며, 새 흐름과 충돌한 과거 제작 순서만 복원하지 않는다.
- 대본·주요 전제 재구성 시 전체 수정본과 필요한 계획을 먼저 제시한다. 새 변경 범위의 제작 승인 전 추가 이미지·TTS·합성을 보류하며, 승인된 같은 범위의 수정 권한과 기존 유효한 승인은 유지한다. 제작 승인과 최종 MP4 전체 청취 승인을 혼동하지 않는다.
- 기획 단계의 전체·씬·전투 시간은 **계획/추정**, 생성한 음성과 최종 타임라인에서 확인한 시간은 **실측**으로 표시한다. 전투 구간의 시작·종료와 포함/제외 이유를 대본·씬·cue에 연결하고 실제 합계를 보고한다. 기술 검사만으로 음성 자연스러움 PASS나 사용자 전체 청취 완료를 기록하지 않는다.

## 적용 범위와 현재 저장 위치

- 신규 쇼츠의 기본값은 계속 `showdown_detail_v5`다. 롱폼은 별도 형식이며 기존 쇼츠·완료 편·진행 편·프로필·승인·검수 이력을 변경하지 않는다. [쇼츠와 공통 제작 규칙](production_rules.md), [자동 기획](automatic_planning.md), [공유 진입점](shared_system.md), [결정 기록](decision_log.md)을 함께 읽는다.
- 두 형식에 공통인 원전·판본 확인, 금지 기준, 한국 인명 전체 이름, 기존 화풍·화자, Gemini 금지, 외부 서비스 승인, 수정 한도·해시·재개·실제 검수·전달 검증은 유지한다. 롱폼에서 달라지는 규격·가변 구성·서사 결말·썸네일·태그·음성 승인·완료 판정에는 이 문서를 적용한다.
- 모든 작업·수정·실행·모델·임시 파일·저장은 `D:\유튜브 자동 쇼츠 생성`이 기준이다. 전달은 `storage_config.json`에 지정된 `D:\유튜브 자동 쇼츠 생성\전달본\<실제 최종 제목>`을 사용한다. 쇼츠의 태그 형식을 롱폼에 강제하지 않지만 제목과 전달 폴더 이름의 일치 및 다른 작업 덮어쓰기 금지는 유지한다.
- 보존 이력의 2026-11-18 원문 13절에서 ‘기존 바탕화면·제목 폴더 규칙을 유지’는 현재 D 전달 정책과 제목 폴더 규칙을 유지한다는 뜻이다. C 바탕화면 저장·옛 `--desktop-root` 기본을 복원하지 않는다. C의 호환 연결과 과거 절대경로 이력은 보존한다.
- **공용 시스템 갱신만으로 개별 작품 제작을 시작하지 않는다.** 특정 작품의 예약·실제 대본·이미지·TTS·렌더는 해당 작품 요청과 유효한 승인 범위에 따른다. 문서의 요구사항과 코드 구현·실행 검증 결과를 구분한다. 현재 수행 범위와 미검증 사항은 실제 작업 보고에 기록하며, 규칙 저장만으로 기능 검증이나 작품 완료를 주장하지 않는다.

## 형식별로 달라지는 핵심

| 항목 | 신규 쇼츠 | 롱폼 |
|---|---|---|
| 기본 프로필 | `showdown_detail_v5` | `showdown_story_long_v1` |
| 최종 실제 길이 | 30~60초 | 시작·결말·CTA 포함 540~900초 |
| 전투 분량 | 저장된 쇼츠 프로필의 구성 유지 | 최종 편집에서 약 3분을 기본 목표로 설계·검토; 정확히 180초인 하드 게이트 아님 |
| 화면 | 1080×1920 세로 | 1920×1080 가로, 30fps |
| 구성 | 기본 화면 9장·14 cue·공방 2회 | 씬·컷·그림·cue·낭독 그룹 수 가변 |
| 결말 | 최종 승패 직전의 미정 질문 | 중심 사건의 결과와 처음 질문에 답하는 결말 |
| 썸네일·태그 | 두 이름과 VS, 기존 쇼츠 태그 | 본편 첫 컷과 별개, 짧은 문구 허용, `#쇼츠` 강제 없음 |
| 최종 음성 승인 | 기존 쇼츠 검수 기준 유지 | 필수 기술 검사와 사용자의 최종 MP4 전체 청취 승인 분리, 로컬 음성 모델은 선택 |
| 전달·완료 | 기존 프로필 검증 | 기술·시각 준비 후 검수용 전달 가능, 전체 청취 승인 전 `NEEDS_REVIEW`, 모든 조건 후 `COMPLETE` |

이 표는 아래 전체 규칙의 요약이며 세부 조항을 생략하는 근거가 아니다. 제작 승인과 최종 음성 청취 승인은 별개다. 유효한 기존 승인은 재요청하지 않으며, 승인 대기는 이미 승인된 범위의 수정 권한을 없애지 않는다.

## 실제 데이터 계약과 제작 승인 연결

아래는 `longform_profile.py`와 `episode_core.py`에 연결되는 형식 계약이다. 스키마 통과는 원전·서사의 타당성이나 시각·음성 검수 PASS를 뜻하지 않는다. 실행 명령과 사용 순서는 [README](../README.md)의 롱폼 안내를 따른다.

| 위치 | 연결 내용 |
|---|---|
| 에피소드 최상위 | `schema_version: 2`, `format: "longform"`, `production_profile: "showdown_story_long_v1"`, 고유 `story_id`(영문·숫자·밑줄·하이픈 1~100자), `cta_presentation: "comment_spoken"` |
| `a`, `b` | 중심 인물의 `name`, 실제 참조 그림 `image`; 선택 판본·근거는 기존 인물 기준/출처와 연결 |
| `story_plan` | `central_event`, `goals`, `motivation`, `information`, `setting`, `abilities`, `progression`, `outcome`, `visualization`의 9항목을 에이전트가 완성 |
| `scenes[]` | 고유 `id`; `objective`, `obstacle`, `action`, `result`, `next_reason`, `location`으로 사건의 인과관계 기록; 참여 인물과 필요한 상태도 본문 규칙대로 추적 |
| `cuts[]` | 고유 `id`, `scene_id`, 안전한 상대 이미지 경로 `image`, 대표 순간 `moment`; 선택 `transition`은 `crossfade` 또는 `hardcut`; 선택 `participants`는 중복 없는 `a`/`b` 목록(빈 목록은 실제 사물/환경 근접 컷) |
| `story_beats[]` | 고유 cue `id`, `scene_id`, `cut_id`, `display_text`, `spoken_text`; `kind`, `condition`, `header`는 실제 역할과 화면에 맞게 사용. 선택 `image`를 넣으면 해당 cut과 같아야 함 |
| `narration_groups[]` | 고유 `id`와 연속 `segment_ids`; 모든 본문 cue 다음 공통 `cta`까지 정확히 한 번, 순서대로 포함. 의미 단위별 여러 그룹을 사용 |
| 선택 `chapters[]` | `title`과 `cue_id`/`cut_id`/`scene_id` 중 하나를 지정. 실제 최종 시간표의 해당 시작 프레임에서 타임스탬프 계산; 여러 씬을 한 챕터로 묶거나 일부 경계만 선택 가능 |
| 선택 `planning.related_short` | 기존 쇼츠의 `job_id`, 프로젝트 기준 `episode_path`, `relationship: continuation 또는 new_event`, 판본·연속성 `compatibility_notes`, 질문 유지/변경 `question_decision`, 실제 읽은 `episode.json`/`source_records.json`/`character_bible.json`의 `reference_hashes` |
| `resolution` | `objective_resolved: true`와 구체적인 `outcome`; 명시적 연작/열린 결말 예외라면 `objective_resolved: false`, `open_ending_request.user_statement`, `resolved_part`, `remaining_question`, `outcome`을 함께 기록 |

- 씬·컷·cue·낭독 그룹의 수는 고정하지 않는다. 모든 선언한 씬/컷은 실제 cue에 연결하고, 중간에 다른 장소나 순간으로 갔다가 돌아오면 별도 안정 ID를 사용한다. 화면 파일 자체의 재사용 여부와 사건 단위 ID를 구분한다.
- `story_beats`에 CTA를 직접 넣거나 에피소드 `cta`로 바꾸지 않는다. 공통 엔진이 마지막 cut 그림에 정확한 댓글 요청 cue 하나를 덧붙인다. `narration_groups`는 그 `cta`도 포함한다.
- 실제 이미지 경로는 에피소드 안의 안전한 상대경로를 쓴다. 절대경로·상위 폴더 이동을 장면 파일명으로 사용하지 않는다. 대표/썸네일/실제 컷의 검수 대상은 실제 연결에서 계산한다.
- `production_authorization.json`은 현재 전체 대본·전제를 사용자가 승인했다는 실제 근거를 기록한다. `approved: true`, `approval_scope: "full_script_and_premises"`, 현재 `script_hash`, 실제 `user_statement`가 필요하다. 파일 형식을 아는 것이 승인 근거는 아니며 임의로 승인 문장을 만들지 않는다.
- 해당 전체 대본·전제 승인은 이미지 생성·TTS·렌더 전에 확인한다. 코드가 확인하는 TTS·렌더 게이트만 통과했다고 이미지 선행 생성이 허용되는 것은 아니다. 이미 승인된 범위의 수정은 사용자에게 같은 승인을 다시 요구하지 않고 그 변경 지시와 적용 범위를 기록한다. 현재 대본/전제 해시와 근거를 일치시키며, 기존 승인을 새 사건·조건·결말의 승인으로 확대하지 않는다.
- `chapters`가 없으면 실제 씬 전환과 씬의 `title` 또는 `objective`에서 챕터를 만들며 내부 ID를 시청자용 제목으로 내보내지 않는다. 설명의 챕터는 계산한 실제 시간·제목·순서와 맞아야 한다. 썸네일은 본편 첫 장면과 독립적이며 최종 전달에 대체 썸네일을 쓸 때도 원본 전체·세부·작은 목록 관찰과 현재 해시가 필요하다.
- 연계 쇼츠는 실제 읽은 동일 인물 조합의 판본·근거·기준 그림을 현재 해시로 확인한다. 최종 완료 시 현재 `relationship`과 쇼츠 작업 ID에 맞는 초안만 `linked_short_comment.txt`로 전달하며 연계를 없앤 뒤 남은 옛 초안을 새 전달본에 포함하지 않는다. 실제 게시/고정은 하지 않는다.
- 새 대본·새 사건의 형식 통과와 제작 승인, 최종 영상의 기술 검사와 사용자 전체 청취 승인은 각각 다른 단계다. 코드 검사는 사용자의 실제 발언 의미나 원전 본문·인과·인체 구조를 대신 판단하지 않는다.

- 롱폼 지원 때문에 쇼츠용 상수를 전역으로 바꾸거나 기존 에피소드를 일괄 변경하지 마.

- Gemini 사용 금지, 유료 서비스·새 계정·외부 전송에 관한 기존 승인 범위를 유지해.
- 실제 검수와 형식 검사, 자체 QA와 사용자 수락의 구분을 유지해.
- 롱폼의 최종 음성 승인에는 12절의 사용자 청취 기준을 적용해. 기존 쇼츠의 음성 검수 기준은 유지해.
- 기존 수정 한도·수정 이력·해시·재개·중복 방지·전달 검증을 유지해.
- 규칙은 실제 프로젝트 문서에 저장하고, 이후 작업 시작 시 읽고 적용하도록 연결해.
- 대화에서 ‘숙지했다’고 말하는 것만으로 시스템 반영을 완료했다고 보고하지 마.
- 특정 편의 장소·무기·결말·예외를 모든 편의 공통 규칙으로 승격하지 마.

## 2. 롱폼의 공통 제작 규격

- 제작 형식: longform
- 프로필: showdown_story_long_v1
- 같은 프로필이 이미 있으면 현재 구현을 확인하고 필요한 내용을 보완해. 중복 프로필을 만들지 마.
- 최종 MP4 전체 실제 길이: 540~900초, 즉 9분 이상 15분 이하.
- 9분·11분·13분·15분 중 특정 길이를 강제하지 마. 사건에 필요한 길이를 범위 안에서 선택해.
- 시작·본문·결말·댓글 안내·전환을 모두 전체 길이에 포함해.
- 기본 화면: 가로 16:9, 1920×1080, 30fps.
- 영상·음성: 기존 H.264/yuv420p MP4, AAC 및 검증된 합성 기술 활용.
- 기본 표현: 기존 화풍의 정지 일러스트와 기존 화자 중심의 내레이션.
- 기본 BGM 없음, 줌·이동·흔들림 없음은 유지해.
- 중심 인물은 기본 두 명으로 하고, 조연은 사건에 필요한 역할만 맡겨.
- 무관한 제3의 강자나 군대가 등장해 중심 인물의 갈등을 대신 해결하는 구조로 만들지 마.
- 그림 수·화면 컷 수·자막 cue 수·공방 수·챕터 수는 이야기마다 정해.
- 쇼츠의 9장·14 cue·공방 2회·인물별 소개 2 cue·30~60초 제한을 롱폼에 적용하지 마.
- 롱폼의 기본은 한 편의 사건이 결과에 도달하는 이야기다. 쇼츠의 승부 직전 중단을 필수 결말로 적용하지 마.

## 3. 사용자 입력에 따른 자율 선정

이후 실제 제작 요청을 받으면 사용자가 준 정보와 기존 기록을 바탕으로 다음처럼 처리해.

1) 인물 두 명을 지정한 경우

- 지정한 조합을 우선 검토해.
- 두 인물의 특성에서 사건·목표·갈등·결말을 구성해.
- 새로운 장소나 조건은 기획안에 명시하고, 이미 승인된 조건이라고 가정하지 마.

2) 인물 한 명만 지정한 경우

- 해당 인물의 판본·배경·능력을 확인해.
- 기존 선정 기준과 이력을 확인하고 적합한 상대를 자율적으로 선정해.
- 그 상대와 이야기가 성립하는 이유를 함께 제시해.

3) 주제·분위기·사건 유형만 지정한 경우

- 지정한 방향에 맞는 인물 조합과 사건을 함께 선정해.
- 지정하지 않은 줄거리·목표·결말은 네가 구성해.

4) ‘롱폼 한 편 만들어’처럼 구체적인 지정이 없는 경우

- 현재 진행 작업, 처리 가능한 롱폼 대기열, 후보·완료·거절 이력을 확인해.
- 기존 선택 순서와 사용자 의도를 따르되 적절한 후보가 없으면 새 조합을 조사해.
- 인물 조합과 새로운 이야기를 선정하고 전체 기획·대본까지 진행해.
- 사용자에게 인물·의뢰·장소·결말을 하나씩 정해 달라고 넘기지 마.

5) 사용자가 줄거리·조건·결말 일부를 지정한 경우

- 지정한 부분을 우선하고 나머지만 합리적으로 구성해.
- 서로 양립하지 않는 조건이나 중요한 근거 부족이 있으면 문제와 구체적인 대안을 설명해.
- 자료를 확인하면 해결할 수 있는 사항은 먼저 조사해.

6) ‘이어 해’, ‘수정해’, ‘새로 만들어’인 경우

- 기존 작업 ID·단계·승인 범위·변경 요청을 먼저 확인해.
- 재개·부분 수정·새 작품·명시적 재제작을 구분해.
- 이미 진행 중인 작품을 새 작업으로 중복 예약하지 마.

쇼츠와 롱폼은 현재 요청과 문맥으로 구분해.
문맥상 롱폼이 분명하면 반복해서 확인하지 마. 쇼츠의 기존 기본값은 유지해.
명확한 새 작품 요청이 없는데 기존 작품을 임의로 다른 인물이나 줄거리로 바꾸지 마.

## 4. 캐릭터 조사에서 이야기를 만들어 내는 방법

이야기를 정해 놓고 인물 이름만 끼워 넣지 마.
아래 연결을 따라 인물의 특성이 사건의 원인이 되게 구성해.

배경·성격·가치관·능력·한계
→ 원하는 것과 지키려는 것
→ 상대와 목표가 부딪히는 이유
→ 그 인물다운 선택과 행동
→ 행동이 만든 결과와 새로운 문제
→ 다음 선택과 사건의 결말

인물별로 다음을 확인해.

- 정체, 출전, 사용할 판본과 시기.
- 살아온 배경이나 처지가 현재 행동에 주는 영향.
- 중요한 가치관과 행동 성향.
- 얻으려 하거나 지키려 할 만한 것.
- 확인된 능력·무기·기술·대표 활약.
- 확인된 한계와, 알 수 없어 단정할 수 없는 부분.
- 어떤 상황에서 강점과 성격이 잘 드러나는지.
- 상대의 특성이 이 인물에게 어떤 문제를 만드는지.

원전에 없는 욕망·감정·선택을 창작할 수는 있지만, 원전의 사실이라고 소개하지 마.
원전에 등장한 대표 활약은 능력 이해의 근거로 활용해. 매번 그 사건을 그대로 재연하는 데 그치지 마.
인물 조사 내용을 영상 앞에서 전부 읽지 말고, 현재 사건을 이해하는 데 필요한 부분을 적절한 시점에 사용해.

선정 단계에서는 원전 근거, 대진 이유, 인물 고유성, 사건의 완결성, 시각화 가능성, 기존 편과의 차이를 함께 판단해.
확인되지 않은 인지도나 자체 점수를 실제 인기·조회수 예측치로 말하지 마.

[기존 쇼츠를 조사 출발점으로 활용]

- 같은 인물 조합의 쇼츠가 있으면 source_records, character_bible, 해당 대본의 핵심 떡밥·마지막 질문·가상 전제를 먼저 읽어.
- 해당 이름의 파일이 없으면 실제 프로젝트의 대응 기록을 찾아. 없는 기록을 읽었다고 보고하지 마.
- 여러 편이 있으면 이번 판본과 사건에 적합한 편을 선택하고 연결할 작업 ID를 남겨.
- 선택 판본·시기·능력 해석·복장·외형 기준이 맞는지 확인해.
- 기존에 확인된 근거는 재사용하고, 새 주장·달라진 판본·불확실한 해석에 필요한 부분을 추가 조사해.
- 쇼츠에 등장했다는 이유만으로 사실이라고 간주하지 마. 창작 상황·약점·조건을 원전 설정으로 승격하지 마.
- 쇼츠의 마지막 질문이 이번 롱폼의 판본·전제·성공 조건과 자연스럽게 맞으면 중심 질문으로 이어받고 영상 안에서 답해.
- 맞지 않으면 새 질문을 만들고, 이어받지 않은 이유를 기존 기획 기록에 한두 문장으로 적어.
- 같은 질문 문장이라도 조건이 달라졌다면 같은 사건의 답처럼 포장하지 마.
- 쇼츠의 장면을 직접 이어가는 경우 기존 위치·소지품·능력 조건·목표를 확인하고 연속성을 지켜.
- 별개 사건을 만드는 경우에는 새 사건이라는 점이 드러나게 해.
- 관련 쇼츠가 없어도 롱폼을 제작할 수 있어. 쇼츠를 먼저 만들도록 강제하지 마.
- 쇼츠 원본·기록은 수정하지 마. 연결 정보와 추가 조사 결과는 롱폼의 기존 기록에 남겨.

## 5. 매 작품에서 네가 스스로 완성할 기획 항목

아래 항목은 사용자에게 입력을 요구하는 질문지가 아니다.
선정한 인물과 확인한 자료를 바탕으로 네가 정리하고, 완성된 기획안으로 제시해.

1) 중심 사건과 질문

- 이번 영상에서 시작해 끝까지 따라갈 사건을 정해.
- 그 사건에서 생기는 핵심 의문을 한 문장으로 정해.
- 질문을 항상 승패·명중·포획으로 고정하지 마.
- 제목·도입·본문·결말이 같은 관심사를 다루게 해.

2) 양쪽의 목표와 성공 조건

- 각 인물이 무엇을 얻거나 지키려 하는지 정해.
- 무엇을 달성하면 성공이고 무엇이 실패인지 구분해.
- 두 인물의 목표가 반드시 같을 필요는 없지만 서로 어떻게 영향을 주는지 명확해야 해.

3) 행동 동기와 이해관계

- 왜 이 인물이 지금 행동하는지, 왜 이 사건에 관여하는지 정해.
- 실패하면 무엇을 잃거나 어떤 문제가 생기는지 정해.
- 단순히 ‘의뢰를 받았다’거나 ‘상대가 나타났다’는 말로 동기를 대신하지 마.

4) 정보와 판단

- 각 인물이 아는 사실, 모르는 사실, 믿고 있는 정보를 정해.
- 새로운 정보가 들어오면 행동이 어떻게 달라지는지 연결해.
- 오해나 비밀이 필요하지 않은 이야기에는 억지로 만들지 마.

5) 장소와 상황

- 지형·출입구·이동 경로·위험 요소 중 사건에 필요한 것만 정해.
- 서로 다른 지역·시대의 인물이 만나는 것은 가상 세계의 전제로 설정할 수 있어.
- 실제 역사에서 만난 것처럼 꾸미지 마.

6) 능력과 상황적 제약

- 원전에서 확인한 능력·무기·한계와 창작한 사건 조건을 구분해.
- 현재 목표와 상황이 어떤 행동을 가능하게 하거나 어렵게 하는지 정해.
- 긴장감을 위해 능력을 갑자기 삭제하거나 새 약점을 만들지 마.

7) 사건의 진행과 선택

- 첫 행동이 어떤 결과를 낳는지 정해.
- 그 결과 때문에 어떤 새로운 선택이 필요한지 연결해.
- 같은 시도와 실패만 반복하지 마.

8) 사건의 결과

- 중심 질문에 이번 영상에서 어떤 결과로 답할지 정해.
- 인물이 목표를 바꾼다면 바꾸는 이유와 과정 자체를 보여줘.
- 제작한 사건의 결과와 원전의 공식 승패를 구분해.

9) 시각화·시간·제작량

- 필요한 씬·장소·조연·화면 컷·새 이미지·재사용 자산을 계획해.
- 9~15분 안에서 자연스러운 분량을 선택해.
- 그림으로 전달하기 어렵거나 제작량이 과도하면 먼저 사건과 구도를 단순화해.

## 6. 사건 유형과 이야기의 다양성

- 인물의 특성과 목표에 맞는 사건 유형을 매번 선택해.
- 의뢰·추적·탈출·보호·회수·경쟁·약속·가치관 충돌 등은 선택 가능한 유형이지 필수 구성 요소가 아니야.
- 모든 편을 의뢰로 시작하거나 한쪽이 다른 쪽을 쫓는 이야기로 만들지 마.
- 오해 해소, 숨은 악인, 공동의 적, 동맹 결말, 마지막 한 발 같은 전개를 고정 공식으로 사용하지 마.
- 인물의 배경과 개성에 따라 도입·갈등·장소의 역할·핵심 행동·해결 방식이 달라져야 해.
- 이름과 장소만 바꾸고 같은 줄거리를 반복하지 마.
- 기존 편들과 갈등 원인, 양쪽 목표, 주요 전술, 중요한 발견·선택, 해결 방법이 지나치게 겹치는지 확인해.
- 모든 요소가 매번 달라야 한다고 강제하지는 마. 같은 인물 조합도 새로운 사건을 만들 수 있고, 다른 조합도 같은 이야기를 반복할 수 있어.
- 서사 다양성을 인물 이름의 중복 여부만으로 판정하지 마.
- 새 이야기임을 설명하려고 근거 없는 능력·복잡한 조연·불필요한 반전을 추가하지 마.

## 7. 기본 뼈대와 사건의 인과관계

아래를 기획의 기본 뼈대로 사용해.
이야기에 맞지 않으면 순서·배치·비중을 조정하고, 중요한 변경 이유를 기존 기획안에 한두 문장으로 적어.
기획 중 뼈대를 조정했다는 이유만으로 별도의 예외 승인이나 새 검수 파일을 요구하지 마.

1) 도입

- 첫 약 30초 안에 사건의 긴장된 순간·위기·핵심 의문을 보여주는 것을 편집 목표로 삼아.
- 관객이 무엇을 보게 될지 이해할 수 있어야 해.
- 맥락 없는 결전 장면이나 결말 미리보기를 매번 강제하지 마.

2) 인물 A의 이해

- 이번 사건의 행동을 이해하는 데 필요한 원전 활약·성격·능력만 짧게 소개해.

3) 인물 B의 이해

- 같은 기준으로 이번 사건과 관련된 부분만 소개해.

4) 사건 발단

- 두 인물이 원하는 것과 그 목표가 부딪히는 이유를 드러내.

5) 첫 충돌

- 한쪽의 행동과 상대의 대응이 실제 상황을 바꾸게 해.
- 누가 어떤 점에서 유리하거나 불리해졌는지, 무엇을 얻거나 잃었는지 보여줘.
- 반드시 완승·제압으로 끝낼 필요는 없어.

6) 변화

- 앞선 행동의 결과, 새 정보, 인물의 선택 때문에 상황이 달라지게 해.
- 같은 시도를 반복하지 말고 다음 행동의 이유를 만들어.

7) 결정적 충돌

- 앞에서 제시한 능력·조건·단서·선택이 결정적인 행동으로 이어지게 해.
- 두 인물의 대응이 이번 사건의 결과에 어떻게 작용하는지 보여줘.

8) 결말과 마지막 질문

- 시작에서 제시한 중심 질문에 이번 사건의 결과로 답해.
- 그 결과나 선택을 바탕으로 시청자의 의견을 물어.

[A·B 소개의 배치]

- 2·3번은 고정된 독립 챕터가 아니야.
- 두 인물을 앞에서 연속 소개하는 것이 가장 명료하면 짧게 사용해.
- 소개 때문에 사건이 멈추면 관련 행동 직전·직후에 나누어 배치하거나 사건 속에 섞어.
- 관련 원전 활약이 확인되지 않으면 만들어 넣지 말고 확인 가능한 특성만 사용해.
- 두 인물의 소개 시간을 똑같이 맞추거나 긴 전기를 낭독하지 마.

[두 인물의 역할]

- 두 인물 모두 확인된 능력·성격이 드러나는 행동이나 선택으로 사건에 실제 영향을 주어야 해.
- 한쪽을 수동적인 과녁이나 상대 설명용 인물로 만들지 마.
- 양쪽의 우세가 자연스럽게 바뀌는 전개는 사용할 수 있어.
- 반드시 한 번씩 우세하게 만들거나, 능력 격차를 지워 대등하게 맞추지는 마.
- 유리함은 공격 성공뿐 아니라 위치 확보·정보 획득·보호·도주·목표 달성 등 이번 사건의 목적에 맞게 보여줄 수 있어.
- 우세를 교대시키려고 갑작스러운 약점·실수·능력 제한을 만들지 마.

[인과관계와 분량]

- 첫 화면부터 이야기의 사건이나 관심사를 보여줘.
- 도입의 약 30초는 편집 목표이며 흥행 공식이나 기계적 합격선이 아니야.
- 긴 인사·채널 소개·인물 전기 나열로 사건 시작을 미루지 마.
- 원전 활약 설명과 회상은 현재 사건을 이해하는 데 필요할 때 사용해.
- 회상과 현재를 구분하고, 돌아온 뒤 현재 위치·목표가 명확해야 해.
- 장면마다 정보·목표·위험·위치·관계·소지품·선택지 중 필요한 변화가 있어야 해.
- 앞 장면의 결과가 다음 장면의 이유가 되어야 해.
- 한마디로 해결될 문제를 특별한 이유 없이 오래 끌지 마.
- 우연한 구원자나 갑자기 생긴 능력·약점으로 결말을 해결하지 마.
- 결정적인 대응과 결말에 필요한 단서는 미리 제시해.
- 관객이 알아야 할 위치·조건을 숨겨 생긴 혼란을 반전으로 포장하지 마.
- 반복 설명, 같은 공방, 불필요한 우회, 긴 무음으로 시간을 채우지 마.
- 본문에 없는 장면이나 끝내 답하지 않을 질문을 제목·썸네일로 약속하지 마.

## 8. 원전과 창작의 공통 경계

[확인된 근거가 필요한 것]

- 원전의 사실로 소개하는 정체·배경·성격·대표 활약.
- 능력·무기·기술과 중요한 한계.
- 승부에 영향을 주는 발동·해제 조건·효과 범위.

[새 이야기로 구성할 수 있는 것]

- 만남·사건·장소·상황·의뢰·갈등.
- 이번 사건에서의 목표·선택·대사·전술.
- 설정한 조건 안에서 벌어지는 행동과 그 결과.

[적용 규칙]

- 원전의 인물 설정과 이번 영상에서 창작한 사건을 명확히 구분해.
- 서로 다른 판본에서 유리한 능력만 가져와 합치지 마.
- 실존 인물과 그를 모델로 만든 소설·희곡 인물의 설정을 섞지 마.
- 새 대사를 원전의 실제 발언처럼 인용하지 마.
- 자료가 없으면 확인되지 않았다고 남기고, 필요한 주장은 삭제하거나 확인 가능한 내용으로 바꿔.
- 강한 능력으로 사건을 바로 해결할 수 있다면 그 가능성을 검토해.
- 사용하지 않는 이유가 필요하면 인물의 목표·보호 대상·상황·선택과 연결하고 앞에서 제시해.
- 능력 고장, 갑작스러운 사용 횟수 제한, 설명되지 않은 무효화 같은 편의적 제약을 만들지 마.
- 원전에 없는 물리적 성질이나 약점을 사실처럼 추론하지 마.
- 새로운 사건 조건은 기획안과 대본에서 밝혀 일관되게 적용해.
- 처음의 성공 조건을 결말에서 다른 조건으로 몰래 바꾸지 마.
- 창작 결과를 공식 승패·객관적인 강함 순위·실제 역사라고 주장하지 마.
- 초반의 자연스러운 표현과 영상 설명에서 원전 인물 설정을 활용한 가상 이야기임을 밝혀.

출처 기록은 기존 sources.md와 source_records.json 등을 활용해.
실제 원전 주장에는 읽은 본문 URL·위치·판본과 문장을 연결해.
창작 장면은 hypothetical로 구분하고, 존재하지 않는 출처를 억지로 붙이지 마.

## 9. 문체·대사·구체적인 행동

- 기본은 기존 화자의 자연스러운 내레이션으로 해.
- 직접 대사는 인물의 선택·감정·대립을 보여주는 데 필요한 순간에 사용해.
- 같은 화자가 읽어도 누가 말하는지 이해되게 작성해.
- 다인 성우·새 음성 서비스는 기본 필수 기능으로 추가하지 마.
- 짧고 명확한 구어체를 쓰고 낯선 이름·지명·설정을 한꺼번에 쏟아내지 마.
- 긴 수식과 감정 설명, 같은 정보의 반복으로 분량을 채우지 마.
- 배경 묘사는 위치·위험·선택을 이해하는 데 필요한 만큼 사용해.
- 임의의 능력치·승률·무적·유일한 약점을 만들지 마.

각 공방이나 연결된 행동 묶음에서 다음이 이해되어야 해.

누가 / 무엇을 이용해 / 무엇을 대상으로 / 어떻게 행동했고 / 무엇이 달라졌는지

- 모든 자막 cue마다 다섯 요소를 반복하지 마.
- 직전 맥락에서 분명한 주어·도구·대상은 자연스럽게 생략할 수 있어.
- 관찰·판단은 무엇을 보고 알아냈으며 다음 행동이 어떻게 달라지는지 확인해.
- ‘몰아붙인다·빈틈을 노린다·압도한다·맞선다·격돌한다·반격한다’만으로 공방을 설명하지 마.
- 이런 표현이 있더라도 구체적인 행동과 결과가 맥락에 있어야 해.
- 단어 경고는 보조 검사로 사용하고, 경고가 없다는 이유로 좋은 대본이라고 판정하지 마.
- 접속어의 반복보다 실제 원인과 결과의 연결을 확인해.
- 특정 인물의 개성이 드러나지 않는 일반적인 공격·방어만 나열하지 마.

## 10. 씬·그림·자막·음성의 단위와 연속성

다음 네 단위를 구분하고 1:1로 강제하지 마.

- 씬: 장소·시간·주요 목표가 이어지는 이야기 단위.
- 화면 컷: 정지 그림으로 보여주는 대표 순간.
- 자막 cue: 한 번에 표시하는 자막 단위.
- 낭독 그룹: 자연스럽게 이어 읽는 문장 묶음.

한 씬에 여러 컷이 있을 수 있고, 한 컷에서 자막은 여러 번 바뀔 수 있어.
그림이 바뀌어도 같은 문장의 낭독이 이어질 수 있어.
자막을 나눴다는 이유로 그림이나 TTS 요청을 하나씩 추가하지 마.

기존 storyboard와 관련 데이터에 아래를 연결해.

- 안정적인 씬·컷·cue·낭독 그룹 ID.
- 인물·장소·목표·방해·행동·결과·다음 씬의 이유.
- 컷별 이미지와 핵심 순간, 관련 cue.
- 원전 근거와 창작 구분.
- 다음 장면에 영향을 주는 상태 변화.

연속성 확인 대상:

- 위치·이동 방향·공격 방향.
- 무기·도구·짐 등 중요한 소지품.
- 문·담·통로·장애물 등 장소의 구조.
- 부상·피로·손상 등 행동에 영향을 주는 상태.
- 각 인물이 알고 있는 정보.
- 능력의 확인된 조건과 사건의 제약.

모든 상태를 매 cue에 복사하는 복잡한 시스템을 만들지 마.
장면 삽입 때문에 기존 ID가 전부 바뀌어 재사용이 무효화되지 않게 해.

## 11. 그림·편집·썸네일의 공통 규칙

- 인물 기준과 화풍을 재사용하되 이번 판본·시기·복장에 맞는지 확인해.
- 기존 쇼츠의 원본 자산을 수정하지 마.
- 가로 화면에 맞게 장면을 구성하고, 세로 그림을 가로로 늘여 인체를 변형하지 마.
- 각 그림은 핵심 순간 하나를 보여줘.
- 연결된 대본은 그 순간의 짧은 원인과 직접 결과를 설명할 수 있어.
- 여러 장소·여러 단계의 행동을 한 정지 그림에 모두 담으라고 요구하지 마.
- 대사에서 행동 상태가 크게 바뀌면 화면도 그 변화를 전달해야 해.
- 전체 구도로 위치를 설명하고 필요한 순간에는 손·무기·시선·단서의 근접 구도를 사용해.
- 모든 컷에 두 인물의 전신을 강제하지 마. 누구의 행동인지와 앞뒤 관계는 명확해야 해.
- 기존 신체·손·관절·무기·접점·복장·기마·크롭 검수 기준을 유지하고, 아래 실제 시각 검수·수정·재검수 절차를 적용해.
- 피·절단·잔혹한 부상은 넣지 마.
- 원본 이미지 수와 화면 컷 수를 구분해.
- 같은 그림은 인물·장소·무기·상태가 맞을 때만 재사용해.
- 긴 정지 구간은 유지시간과 이유를 확인해. 말로 여러 사건이 진행되는데 화면이 그대로인 구간을 줄여.
- 일정 초마다 무조건 그림을 바꾸거나 고정 그림 수를 채우지 마.
- 생성 전에 예상 새 이미지 수·재사용 수·컷 수를 제시해.
- 제작량이 과도하면 먼저 장소·조연·구도를 단순화해.

[생성 전 동작·접점 설계]

- 주요 행동 컷은 누가 어느 손으로 무엇을 잡고, 어디를 향해 움직이며, 상대가 어떻게 반응하는지 정해.
- 몸의 방향·손과 무기의 접점·발과 지면의 관계·인물 간 거리가 그 순간의 행동과 맞는지 먼저 확인해.
- 인물 기준 이미지와 해당 무기·복장 자료를 활용하고, 불필요하게 복잡한 손짓·겹침·원근은 줄여.
- 대본의 핵심 행동이 잘 보이는 구도를 선택해. 확인하기 어려운 자세를 프롬프트 문구만으로 해결됐다고 간주하지 마.

[원본 이미지의 실제 시각 검수]

- 새로 생성하거나 수정한 모든 이미지를 실제로 열어 전체 구도부터 확인해.
- 손가락·손목·관절·다리·발·얼굴·무기와 접점 등 필요한 부위를 확대해서 확인해.
- 작은 미리보기나 여러 컷을 작게 모은 화면만 보고 세부 검수를 끝내지 마.
- 생성 성공 메시지·프롬프트·파일명·해상도·해시 확인은 시각 검수를 대신하지 못해.

확인할 항목:

- 손·손가락: 인물 설정에 없는 손가락 추가·융합·분리, 어색한 길이와 꺾임, 엄지 위치, 손목 연결을 확인해.
- 팔·관절: 어깨→팔꿈치→손목→손의 연결과 길이·방향을 확인해. 겹친 두 인물의 팔이 합쳐지거나 다른 인물의 손처럼 이어지지 않아야 해.
- 다리·발: 골반→무릎→발목→발의 연결, 발 방향, 다리의 추가·소실·비정상 꺾임을 확인해. 서기·달리기·점프 등 해당 순간에 맞는 균형과 지지 관계를 확인해.
- 얼굴·몸통: 얼굴과 목·어깨 연결, 시선·머리·몸통 방향, 인물의 비율이 자세와 화풍 안에서 자연스러운지 확인해.
- 무기·소품: 손잡이·칼날·창대·활·시위·화살 등 해당 도구의 구조와 연결이 유지되는지 확인해. 이유 없이 휘거나 끊어지거나 두 개로 늘어나거나 다른 물체와 합쳐지지 않아야 해.

- 인물 간 행동: 공격·방어·회피의 방향과 거리, 접촉 위치가 대본과 맞는지 확인해. 무기가 닿지 않았는데 막은 것으로 보이거나 다른 인물의 신체와 섞이지 않아야 해.
- 장면 연속성: 무기 종류·형태·소지품·복장·손상·잡는 손이 이유 없이 바뀌지 않는지 확인해. 화면의 좌우와 인물의 실제 왼손·오른손은 구분해.

- 마지막 그림을 실제 발화 길이만큼 유지하고 긴 고정 CTA로 분량을 채우지 마.

[메타데이터·출력]

- 롱폼 제목은 영상이 실제로 답하는 중심 질문을 짧게 쓴 것으로 해.
- 누구의 어떤 사건인지 알아볼 수 있게 하고, 대본의 목표·성공 조건과 제목의 질문을 일치시켜.
- 제목·썸네일 문구·대본·자막·설명·댓글의 맞춤법을 확인해.
- 화살 등을 목표나 과녁에 명중시킨다는 뜻은 ‘맞히다’로 써. 시간·규격을 일치시킨다는 뜻의 ‘맞추다’와 구분해.
- 롱폼에 #쇼츠나 쇼츠의 태그 순서를 강제하지 마.
- 설명에는 선택 판본·확인한 출처·가상 창작이라는 설명·실제 사용한 AI 이미지와 합성 음성을 적어.
- 제목·썸네일·대본·설명·댓글이 같은 사건과 조건을 말해야 해.
- 챕터 타임스탬프는 실제 최종 시간표에서 만들어.
- 고정 댓글은 초안만 작성하고 명시적 요청 없이 게시하지 마.
- 영상·SRT·썸네일·제목·설명·댓글·출처·QA·manifest의 기존 전달 체계를 활용해.
- OS가 확인한 실제 바탕화면과 최종 제목 폴더 규칙을 유지해.
- 형식과 작업 ID로 출력을 구분하고 기존 쇼츠·다른 롱폼 파일을 덮어쓰지 마.
- 청취 승인 전 검수용 전달과 승인 후 최종 완료·전달 확정을 구분해. 승인된 영상을 이유 없이 다시 생성하지 마.

[쇼츠 연결 댓글]

- 실제로 연결할 같은 인물 조합의 쇼츠가 있으면, 롱폼 최종 완료 시 해당 쇼츠용 고정 댓글 초안을 하나 더 제공해.
- 기본 문구: ‘이 대결의 전체 이야기는 롱폼에서 확인하세요. [롱폼 영상 링크]’
- 해당 쇼츠의 질문·사건을 이어받은 경우에는 기본 문구를 사용해.
- 같은 인물 조합의 별개 사건이라면 ‘이 두 인물의 새로운 이야기는 롱폼에서 확인하세요. [롱폼 영상 링크]’처럼 실제 관계에 맞게 바꿔.
- 게시 주소가 없으면 링크 자리를 표시하고, 존재하지 않는 URL을 만들지 마.
- 연결할 쇼츠 ID와 댓글 초안은 롱폼의 기존 전달 자료에 넣고 쇼츠 원본·기록은 수정하지 마.
- 실제 댓글 게시·고정·기존 댓글 수정은 명시적 요청 없이 실행하지 마.

## 14. 문서·코드·중복·검수 연결

## 15. 이후 개별 제작 요청을 처리하는 절차

[새 롱폼 요청]

1) 최신 규칙·진행·후보·완료·거절 이력을 확인해.
2) 사용자 입력 범위에 맞춰 인물 조합과 판본을 선정해.
3) 캐릭터 배경과 특성에서 새로운 사건을 구성해.
4) 기획 아홉 항목과 전체 줄거리를 스스로 완성해.
5) 9~15분으로 계획한 전체 낭독 대본을 작성해.
6) 씬·컷·자막·낭독 그룹·원전 근거·가상 전제·예상 제작량을 연결해.
7) 전체 기획·대본·장면 계획을 한 번에 검토할 수 있게 제시해.
8) 유효한 제작 승인이 없으면 대본과 주요 전제 승인 단계에서 멈춰.
9) 제작 승인이 있으면 이미지·음성·영상을 만들고 필요한 기술·화면 검수와 수정을 진행해.
10) 확인 가능한 최종 MP4·자막·검수 요약을 검수용으로 전달하고 ‘청취 승인 대기’로 보고해.
11) 사용자가 해당 영상을 끝까지 듣고 승인하면 해당 버전의 음성 승인을 기록해.
12) 나머지 완료 기준과 전달 결과를 확인하고 COMPLETE·done을 반영해. 연결할 쇼츠가 있으면 추가 댓글 초안을 함께 전달해.

[승인과 재개]

- 기획 중 인물·장소·질문·결말을 하나씩 승인받으려 하지 마. 완성된 제안과 대본을 먼저 만들어.
- 이미 해당 대본과 전제에 유효한 승인이 있으면 다시 묻지 마.
- 문맥상 제작 진행 승인이 분명하면 특정 승인 단어를 다시 요구하지 마.
- 단순한 대본 이어쓰기 요청을 모든 제작의 승인으로 확대하지 마.
- 단순 ‘이어 해’나 파일 수령을 최종 영상의 전체 청취 승인으로 확대하지 마.
- 청취 승인 대기 중 재개할 때는 사용자 피드백과 현재 결과물을 확인하고, 승인된 자산을 임의로 재생성하지 마.
- 승인 후 그림마다 반복 확인을 요구하지 말고 합의한 범위에서 진행해.
- 제작 승인을 품질 검수 면제·새 서비스 사용·업로드 승인으로 확대하지 마.
- ‘이어 해’는 현재 ID·대본 버전·승인 범위·생성·검수 상태를 확인하고 미완료 단계부터 진행해.
- ‘수정해’는 지정 범위와 영향을 받는 결과만 수정하고 기존 이력을 보존해.
- 사용자가 지정한 수정 범위는 다시 승인받지 마. 요청을 넘는 주요 변경이 필요할 때만 구체적인 변경안을 제시해.
- 이후 사용자의 명시적인 범위 변경은 최신 지시로 반영해.

[개별 작품의 승인용 제출물]

A. 인물 조합·선정 이유·중심 사건·제목과 질문·목표·동기·주요 전제·결말·목표 길이.

B. 시작부터 결말·마지막 질문·CTA까지 전체 낭독 대본.

C. 씬별 목표·방해·행동·결과·다음 씬 연결·장소·계획 시간.

D. 컷·이미지·cue·낭독 그룹 연결, 주요 동작·접점의 검수 포인트와 예상 신규·재사용 제작량.

E. 선택 판본·읽은 출처·확인한 능력·창작 설정·미확인 사항·관련 쇼츠와 질문의 연결 여부.

F. 내용 검토 결과·기본 뼈대의 주요 조정 이유·제작 후 실제로 확인해야 할 품질·길이·사용자 청취 승인 단계.

- 검토하는 사용자에게 결말을 숨기지 마.
- 전체 대본을 씬 제목·줄거리 요약·‘이하 전투 진행’으로 대신하지 마.
- 완전한 대본을 파일로 보존하고 읽을 수 있게 제공해.
- 출력 한도가 있으면 완전한 파일과 접근 가능한 링크를 제공하고 핵심 내용을 설명해. 요약만 만들고 전체 대본 작성 완료라고 말하지 마.
- 대본 단계의 시간은 계획·추정이며 실측이 아니야.
- 대본·주요 전제의 제작 승인 전에는 무료·유료와 관계없이 실제 이미지·TTS·최종 영상 생성을 실행하지 마.
- 대본 제출이나 파일 생성만으로 COMPLETE 처리하거나 done으로 옮기지 마.
- 검수용 결과물을 먼저 전달하고, 최종 완료는 사용자 청취 승인을 포함한 해당 제작·검수·전달 기준을 실제로 충족한 뒤 기록해.

## 16. 이번 시스템 구축 작업의 완료 조건

이번 요청에서는 다음까지만 수행해.

1) 기존 프로젝트 상태와 실제 구현을 확인해.
2) 필요한 변경 파일을 기존 백업·수정 이력 방식으로 보존해.
3) 위 공용 규칙을 문서·프로필·기획·필요한 코드 연결에 반영해.
4) 특정 인물·대진·질문·의뢰·첫 시범편이 기본값으로 남지 않았는지 확인해.
5) 인물 두 명/한 명/주제만/지정 없음/기존 조건/재개/수정의 처리 기준을 확인해.
6) 실제 생성 호출 없는 fixture·mock·형식 검사로 변경 부분을 확인해.
7) 540~900초 경계, 가로 설정, 가변 장면 연결, 낭독 그룹, 형식별 중복, 롱폼 결말과 기존 쇼츠 동작을 필요한 범위에서 확인해.
   롱폼의 기술 검사·청취 승인 상태 분리, 로컬 모델 비필수 처리, 검수본 선전달, 승인 전 COMPLETE 금지, 승인 버전 연결도 확인해.
   쇼츠 자료 참조·질문 연결·별개 사건의 안내 문구·제목 기준이 공용 규칙에 반영됐는지 확인해.

## 2026-11-19 대결 행동·전술 판단 중심 전개와 자연스러운 구도

롱폼에도 [공통 제작 규칙](production_rules.md)의 같은 날짜 최신 절을 적용한다. 상세 기준과 아래 원문은 함께 유지한다.

- 서사의 중심은 두 인물의 대결 행동과 전술 판단이다. 발단·소개·후일담은 공방의 이유와 결과를 이해시키는 만큼 압축하고, 행동 → 상황 변화 → 상대의 대응 → 새로운 상황으로 사건을 진행한다.
- 같은 시도·실패·설명을 반복하거나 억지로 양쪽의 우세를 교대시켜 9~15분을 채우지 않는다. 고정 전투 비율이나 새 공방 횟수는 설정하지 않는다. 원전 능력의 임의 삭제·제한, 새로운 능력·약점으로 대결을 연장하는 방식은 금지한다.
- 최종 길이 540~900초, 가변 씬/컷/cue/낭독 그룹, 중심 사건에 답하는 결말은 유지한다. 설득력 있는 사건이 길이 범위에 맞지 않으면 대본 단계에서 재구성 필요를 보고하며 범위 자체를 임의 변경하지 않는다. 쇼츠의 길이·고정 구성으로 바꾸지 않는다.
- 얼굴 정면 노출을 고집하지 않는다. 후면·측면·어깨너머 구도를 활용해 몸통 앞뒤·팔다리·무기 접점·문과 기둥의 공간 관계를 먼저 자연스럽게 만든다. 몸을 비틀어 얼굴을 노출하거나 인체를 문틀 양쪽으로 나누지 않는다.
- 대본·주요 전제 재구성 요청에는 수정한 전체 대본과 핵심 전제를 먼저 제시한다. 해당 변경 범위의 제작 승인 전 추가 이미지·TTS·합성은 보류한다. 승인된 같은 범위의 수정 권한과 유효한 승인은 보존한다.
- 대본 승인 후 이미지 전체 초안을 먼저 만들고 실제 등장 순서대로 이미지 전용 검토를 받는 아래 순서는 유지한다. 기존 이미지·음성·대본·시간표·검수 기록을 보존하고 재사용/수정/새 제작을 구분한 자산 연결표를 제출한다. 특정 편의 탈출·귀환·승패를 모든 롱폼의 기본 결말로 만들지 않는다.

## 2026-11-19 이미지 전체 초안 먼저 전달·등장 순서대로 검토

사용자는 개별 이미지마다 완벽한 검수·자동 재수정을 이어가느라 지연되는 방식을 바꾸고, “일단 이미지부터 다 만들어”, “내가 이미지 캡처해서 이상한거 있거나 피드백 바라는거 있으면 ... 그때 수정”, “이미지 다 생성했다하면 난 오로지 그땐 이미지만 판단”, “나오는 순서대로 이미지를 나열해”라고 지정했다.

- 승인된 대본·전제의 이미지 초안을 먼저 모두 생성해 한 번에 전달한다. 개별 그림의 자동 수정 반복으로 전체 이미지 초안 전달을 지연하지 않는다. 사용자가 지적한 수정은 해당 피드백 범위에서 진행한다.
- 본편 이미지는 실제 재생 순서대로 01부터 번호를 붙여 나열한다. 씬 ID의 숫자순이나 파일명 알파벳순으로 정렬하지 않는다. 썸네일은 본편 순번에서 분리한다. 원본과 큰 그림으로 볼 수 있는 순서별 검토 자료를 함께 제공한다.
- 이 단계는 이미지 전용 사용자 검토다. 음성·자막·전체 영상이나 최종 청취 승인을 함께 요구하지 않는다. 이미 생성한 음성·시간표는 보존하고 이유 없이 다시 만들지 않는다.
- 초안 생성 완료와 이미지 품질 검수 통과를 구분한다. 알려진 문제·미검수 상태·기존 수정 횟수와 해시를 숨기거나 초기화하지 않는다. 사용자 이미지 의견을 반영한 뒤 필요한 최종 시각·기술 검수와 영상 단계를 진행한다. 이 지시는 최종 품질 검수 면제가 아니다.
