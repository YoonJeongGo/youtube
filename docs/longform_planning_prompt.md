# 롱폼 공용 기획·대본 작성 프롬프트

## 2026-11-20 추가: 다음 롱폼의 노림·근접 공방

[최신 이야기 기준](longform_production_rules.md)과 [근접 공방 기준](longform_combat_direction.md)을 다음 신규 롱폼의 기존 아홉 기획 항목·씬·컷표 안에서 실행해. [사용자 원문](requests/2026-11-20-longform-intent-close-combat-request.txt)의 규칙이며, 현재 승인 편 대본·음성·컷 순서를 다시 작성하라는 뜻이 아니야.

- 숨겼다가 밝히는 장치는 한 편에 최대 한 번으로 계획해. 그 장치의 위치를 표시하고, 나머지 공방은 결과 전에 노림을 먼저 보여 줘. 결과나 결말 전체를 미리 설명하지 마.
- 공방마다 다음 한 줄을 실제 내용으로 채워: **‘노림 → 막음이나 실패 → 대가’**. 무엇을 보고 판단했는지와 왜 성공·실패했는지, 이후 선택에 남는 변화를 기존 progression/information/goals에 연결해.
- 전체 공방의 절반 이상은 승리 조건을 한 뼘 차이로 위협하게 설계해. 해당 공방 수/전체 수와 그 순간의 행동·목표·대응을 적어. 숫자만 맞추는 반복이나 새 능력·약점은 금지야.
- 본 사건의 첫 실제 공방을 영상 시작 3분 안에 배치해. 도입 재탕을 첫 공방으로 대신 세지 마. 예상 시각을 쓰고 실제 음성·영상에서 재측정할 위치를 지정해. 전체 9~15분, 전투 합계 약 3분의 기존 목표와 호흡/TTS 기준은 유지해.
- 전신 측면 둘을 세우는 구도는 공방당 최대 한 장. 나머지는 한 사람이나 눈·손·발·칼끝 근접과 극단 원근으로 설계해. 맞붙을 때는 팔 하나 이내로 붙이고 자연스러운 겹침과 뒷모습을 써. 손 소유와 관절 연결은 지켜.
- 같은 전투 구도는 한 편에 두 번 쓰지 마. 컷표에서 카메라 높이·방향/크기/전경/자세·접점을 비교해. 원화를 조금 확대하거나 손님만 추가해 같은 구도를 반복하지 마.

기존 공방 표에 아래 내용을 함께 기록해. 새 episode 필수 키나 새 검수 상태값을 추가하지 마.

| 공방 | 노림 공개 위치 | 노림 → 막음이나 실패 → 대가 | 위협받는 승리 조건·한 뼘 순간 | 예상 시작·실측 위치 | 전신 측면 수·나머지 구도 |
|---|---|---|---|---|---|
| 실제 대본 식별자 | 실제 cue와 문장 | 실제 인과 | 해당 여부와 행동 근거 | 추정/미측정 구분 | 실제 컷 ID와 구도 |

검토 시 첫 공방의 시작, 위협 공방 수/전체 수, 숨김 장치 수, 공방별 전신 측면 수, 반복 구도 유무를 [대본 검수표](longform_script_review.md)에 증거와 함께 남겨.

2026-11-19 사용자 공통 개편 지시를 적용한다. 롱폼 `showdown_story_long_v1` 전용이며 특정 인물·사건·승패·탈출·귀환·화해를 기본값으로 삼지 않는다. [롱폼 공용 규칙](longform_production_rules.md), [대본 검수표](longform_script_review.md), [공통 이미지 기준](image_geometry_rules.md)을 함께 읽는다. 이후 사용자 지시가 충돌하면 최신 지시와 해당 승인 범위를 우선한다.

근거: [사용자 요청 원문 10절](requests/2026-11-19-longform-story-system-request.txt).

[롱폼 공용 규칙의 현재 추가 기준](longform_production_rules.md)과 [호흡·화면 요청 원문](requests/2026-11-19-longform-pacing-and-cut-defaults-request.txt)을 시간·컷 계획에 함께 반영해. 문장 사이는 0.3~0.5초(기본 0.4초), 같은 장 문단 사이는 0.7초, 장 전환은 1.2초다. 동일 정지 구도는 비전투 20초, 전투 8초를 넘기지 말고 대화는 말하는 인물 쪽 컷으로 바꿔. 기존 그림의 얼굴·손·소품 크롭을 먼저 연결하고 부족한 컷만 새로 계획해. 공통 9~15분을 유지하며, 특정 편의 축약 목표·별도 길이·승인 후 TTS 조건을 모든 편의 기본으로 확대하지 마.

## 추가 적용: 전투 컷의 실제 생성과 편집

[전투 컷 연출·프롬프트·편집 기준](longform_combat_direction.md)의 01~16을 실제 이미지 계획·영문 생성 입력·편집에 적용해. 예비·임팩트·여운·버팀·정지를 구분하고 중요한 타격 2~3개에만 온전한 세 박자를 써. 각 원화에는 한 순간만 그려. 이야기의 사실·정보 공개 순서와 기존 역사 일러스트 인물·선화·채색, 인체·공간이 먼저야.

전투 컷의 실제 영문 입력은 [Beat / script cue] → [Camera] → [Pose] → [Expression] → [Effects] → [Light / background] → [Continuity] → [Characters] → [Style lock] 순서로 써. 내부 컷 ID와 후반 작업 메모를 생성기 지시로 넘기지 말고 보이는 구도로 바꿔. 보이는 대상의 고정 문구와 실제 승인 참조 이미지를 연결하고 소품 명칭을 통일해. 모든 컷에 BASE LOCK, 전투의 예비·임팩트·여운·버팀에만 그 뒤 ACTION LOCK을 원문 그대로 붙여. 원본 문구는 연결 문서 15절에서 가져와.

images.md에는 한글 지시·낭독 시작 어구·참조 ID·실제 최종 영문·생성/부분 수정/재생성 실횟수와 채택 경로를 남겨. 실패한 시도도 세고 원화와 크롭·편집 배치를 구분해. 전투 8초 초과 정지 구도는 대사 속 새 정보에 맞는 승인 원화의 크롭으로 먼저 해결하고 부족한 연결 그림만 추가해. 크롭을 새 접촉·득점처럼 쓰거나 원화에 없는 것을 만들어 내지 마.

편집의 프레임·픽셀·줌·섬광 상한과 소리 정렬은 연결 문서 13절을 그대로 계획하고 실제 영상으로 확인해. 원본 확대와 가로 360px, 그림 순서와 실제 음성 연결 검사를 별도로 해. 특정 편의 합 수·시간·목검/먹 자국·모래시계·결말·시험 이미지 수를 공통 기준으로 가져오지 마.

## 실제 작업에서 사용하는 방법

- 롱폼 요청을 처리하거나 후보 부족으로 `NEEDS_RESEARCH`가 나왔을 때, 실제 조사를 수행하는 Codex가 아래 프롬프트로 기획과 전체 대본을 작성한다. Python의 후보 선택 성공을 대본 작성·내용 검토 완료로 여기지 않는다.
- `plan_matchups.py`는 조사된 후보를 선택·예약한다. 공용 규칙 정리나 기획안 작성만 요청받았다면 실제 작업 예약, 이미지, TTS, 영상 합성을 실행하지 않는다.
- 이 문서의 기획 내용은 기존 `story_plan` 아홉 항목과 씬·컷·cue·낭독 그룹, `storyboard.json`, 기존 검토 문서에 연결한다. 항목별 새 필수 파일이나 새로운 episode 필수 키를 만들지 않는다.
- 현재 대본·주요 전제의 유효한 제작 승인을 확인한다. 승인된 같은 범위는 재질문하지 않고, 범위를 바꾸는 재구성은 수정한 전체 대본과 주요 전제를 먼저 제시한다.

현재 문서를 실제 기획 경로에서 읽는 명령은 다음과 같다. 작업을 예약하거나 미디어를 생성하지 않는 읽기 전용 명령이다.

```powershell
.\run_python.ps1 plan_matchups.py longform-guidance
```

출력된 현재 문서 경로·본문으로 기획하고 [대본 검수표](longform_script_review.md)의 관찰을 남긴다. `longform_candidate_errors`와 `check_episode.py --text-only`의 구조 검사가 실제 내용 판단을 대신하지 않는다. 후보 선택·예약 명령은 별도의 실제 제작 요청과 작업 상태에 맞게 사용한다.

## 공용 프롬프트

사용자의 지정 인물·주제·조건과 현재 작업 기록을 바탕으로, 인물의 구체적인 행동과 선택이 발단부터 결말까지 이어지는 롱폼을 기획하고 전체 낭독 대본을 작성해.

사용자가 지정한 범위는 유지하고 나머지는 조사와 판단으로 완성해. 세부 설정을 하나씩 사용자에게 정해 달라고 넘기지 마. 이전 작품과 같은 대진이면 판본·기존 사건·승인 범위를 확인해 재개와 새 사건을 구분해. 같은 조합의 쇼츠가 있으면 질문·가상 전제·원전 근거·외형 기준을 실제로 읽고, 같은 사건의 후속인지 새 사건인지 밝혀. 기존 자료를 읽었다거나 새 근거를 확인했다고 꾸미지 마.

인물마다 선택 판본의 배경·성격·가치관·능력·무기·한계·대표 활약을 확인해. 그 인물이 무엇을 원하고 지키는지, 상대의 어떤 행동이 문제를 만드는지에서 이야기를 출발시켜. 능력 목록만 읽지 말고 실제 활약으로 그 인물다운 행동을 이해시켜. 소개는 이번 사건에 필요한 만큼 쓰고 이후 필요한 추가 정보만 짧게 보충해.

### 기획 아홉 항목을 완성해

아래 보완 내용은 기존 아홉 항목 안에 적어. `anchor POV`는 소개 이후 주로 따라갈 A 또는 B의 행동 기준을 뜻하며, 새로운 필수 데이터 필드 이름을 뜻하지 않아.

| 기존 항목 | 작성할 내용 |
|---|---|
| 1. 중심 사건과 질문 — `central_event` | 시작부터 끝까지 따라갈 사건, 핵심 질문, 제목·도입·본문·결말의 연결. 이번 편의 질문을 승패·명중·포획 중 하나로 기계적으로 고정하지 마. |
| 2. 목표와 성공 조건 — `goals` | A·B가 얻거나 지킬 것, 성공·실패의 조건, 두 목표의 충돌과 영향. 전투 승리와 원래 목표 달성이 다를 수 있으면 그 관계도 밝혀. |
| 3. 동기와 이해관계 — `motivation` | 지금 행동하는 이유, 배경·성격·가치관과의 연결, 실패하면 잃는 것. 단순히 상대가 나타났거나 의뢰를 받았다는 말로 대신하지 마. |
| 4. 정보와 판단 — `information` | 각자 아는 것·모르는 것·믿는 것, 무엇을 보고 듣고 알아차리는지, 그 정보가 선택을 어떻게 바꾸는지. 필요 없는 오해·비밀은 만들지 마. |
| 5. 장소와 상황 — `setting` | 필요한 지형·출입구·경로·거리·시선·공격 방향·가림 관계, 사건과 관련된 물건·위험. 서로 다른 시대의 만남은 가상 전제로 구분해. |
| 6. 능력과 조건 — `abilities` | 확인된 능력·무기·한계와 창작 사건 조건을 구분해. 강한 능력으로 바로 해결할 가능성과, 사용하지 않는 선택이 있다면 그 근거를 검토해. |
| 7. 진행과 선택 — `progression` | 소개 이후 누구의 진행 중인 행동을 따라갈지와 그 이유, 그가 지금 하는 일·목표. 발단→전개→위기→절정의 행동·상대 대응·결과·다음 판단, 전투 밖 장면의 의미 있는 변화까지 연결해. |
| 8. 사건의 결과 — `outcome` | 중심 사건과 승부 목표가 어떻게 끝나는지, 누가 무엇을 얻고 잃는지. 목표 변경의 원인·선택과 마지막 질문을 정해. 결말의 감정이나 화해 여부를 고정하지 마. |
| 9. 시각화·시간·제작량 — `visualization` | 전체 영상의 예상 길이, 씬별 변화·예상 시간, 전투 구간별 시작·종료·합계와 산정 근거, 공방별 행동/대응/결과, 컷별 핵심 순간·구도·이미지 연결, 신규/수정/재사용 수와 이유. |

### 인물의 이야기로 들어가 사건을 진행해

기본 흐름은 `도입 → A·B 이해 → 한 인물의 진행 중인 행동 → 사건 발단 → 갈등 전개 → 위기 → 결정적 충돌과 절정 → 결말·질문`이야. 이를 같은 길이의 독립 챕터로 강제하지 마.

- 도입 약 30초 안에 사건의 긴장이나 핵심 질문을 제시해. 시청자에게 승패와 결말을 처음부터 설명하지 마. 이는 편집 목표이며 정확한 초 단위의 자동 합격선은 아니야.
- A·B를 이해시킨 뒤 한 인물이 이미 하고 있던 일이나 추구하던 목표를 따라 본 이야기에 들어가. 필요하면 상대 행동을 교차해도 되지만 같은 상황을 양쪽 시점에서 길게 반복하지 마.
- 발단은 인물이 하던 일과 상대 행동이 연결되어 생겨야 해. 싸움을 만들려고 성격에 맞지 않는 선택을 시키지 마.
- 전개에서는 관찰·대화·접근·견제·첫 충돌의 결과가 다음 선택을 만들어야 해. 대화로 풀 수 있는데 싸운다면 왜 해결되지 않았는지 납득시켜.
- 위기는 앞선 선택 때문에 계획이 어긋나거나 목표·위험·대가가 달라져 생겨야 해. 반드시 양쪽에 불리함을 번갈아 배분하지 마.
- 절정에서는 앞서 제시한 능력·성격·판단·위치·단서와 앞선 공방의 결과가 결정적 행동을 만들어야 해. 갑작스러운 능력이나 제3자가 중심 갈등을 대신 해결하지 않게 해.

처음부터 실제 장면으로 써. 인물이 어디서 무엇을 하고, 무엇을 얻거나 지키며, 어떤 변화를 보고 듣고, 어떻게 해석하고 선택해 행동하거나 말하는지, 상대는 무엇을 알고 어떻게 반응하는지, 그 결과 무엇이 달라지는지 이해되게 해. 이 요소를 매 문장에 반복하는 틀로 만들지는 마.

필요한 순간에는 직접 대사를 사용해. 말하는 사람의 성격·목표·의심·정보가 드러나고 그 말 뒤 행동이나 관계가 달라지게 해. 기본은 기존 화자의 자연스러운 내레이션이며 같은 화자가 읽어도 발화자가 분명해야 해. 내레이션은 화면만으로 부족한 맥락·판단·원인을 보태고, 이미 보이는 행동을 같은 뜻으로 반복 설명하지 마.

전투가 없는 장면도 정보·관계·위험·목표의 상태·선택 중 적어도 하나를 의미 있게 바꿔. 관련 없는 풍경·생활 동작·이동·수식과 감정 설명을 늘려 분량을 만들지 마. 한마디면 해결될 오해나 이미 제시한 배경을 특별한 이유 없이 오래 끌지 마.

### 전체 9~15분과 전투 약 3분을 함께 설계해

- 전체는 도입·본문·결말·질문·댓글 안내·전환을 포함한 **최종 실제 영상 540~900초**야. 기획의 예상 길이와 생성 음성/최종 영상의 실측을 구분해.
- 전투는 **완성 영상에서 공방이 전개되는 구간의 합계 약 3분**을 기본 목표로 해. 이야기 속 경과 시간이나 정확히 180초를 맞추는 강제값이 아니야. 고정 전투 비율·공방 횟수·이미지 수나 별도 허용 오차 숫자를 새로 만들지 마.
- 공방은 `행동 → 상대에게 생긴 변화 → 대응 → 새로운 상황 → 다음 판단`으로 연결해. 공격·방어·회피·견제·유인·거리 조절·위치 변경이 서로의 선택과 상황에 실제 영향을 주어야 해.
- 무엇을 보고 판단했고 무엇을 시도했으며 왜 성공·실패했는지 보여줘. 첫 시도의 정보·거리·위치·목표 상태·위험이 다음 행동에 영향을 줘야 해.
- 짧은 전술 판단과 결과 설명은 해당 공방에 연결할 수 있어. 조준·바라보기 설명만 늘리거나 같은 공격과 회피를 반복해 전투 시간을 만들지 마.
- 긴 원전 회상·반복 해설·도입과 본문에 중복 사용한 동일 공방은 전투 목표 시간을 부풀리는 데 사용하지 마. 같은 순간을 다시 보여주는 도입 재탕은 전투 합계에서 중복 산정하지 마.
- 전투가 끝난 이유와 마지막 공방이 결과에 미친 영향을 보여줘. 한쪽이 계속 우세해도 되며 기계적인 성공/실패 배분이나 역전극을 강제하지 마.

기획의 기존 시간표에 아래를 적어. 전투가 나뉘면 여러 행으로 쓰고, 겹치는 시간을 두 번 합산하지 마. 별도의 편별 필수 파일을 추가할 필요는 없어.

| 구간 | 시작·종료 위치 또는 cue | 예상 시작 | 예상 종료 | 예상 길이 | 포함하는 행동·전술 판단 | 제외하는 회상·반복 장면과 이유 |
|---|---|---|---|---|---|---|
| 실제 기획에서 정할 구간 | 실제 대본의 식별자 | 미산정 | 미산정 | 미산정 | 실제 공방 내용 | 해당 시 기록 |

전체 길이와 전투 합계, 산정 방법·가정, 미확인 부분을 함께 적어. 약 3분과 차이가 나면 단순 초과/미달 판정 대신 필요한 공방이 충분한지, 불필요한 연장이 있는지 검토하고 조정 이유를 설명해. 인물의 능력·성격을 지키면서 분량이 성립하지 않으면 설명을 늘려 제작에 넘기지 말고, 원인을 해결한 기획이나 근거 있는 대안을 먼저 제시해. 사용자 지시 없이 전체 9~15분 기준 자체를 바꾸지 마.

### 원전의 능력과 창작 사건을 구분해

선택 판본의 인물 설정·능력·무기·한계는 읽은 근거로 유지해. 서로 다른 판본의 유리한 능력을 합치지 마. 같은 인물에 관한 역사 기록과 소설 설정을 구분 없이 섞지 마. 창작한 만남·장소·목표·선택·대사·전술·결과를 원전 사실이나 실제 발언처럼 소개하지 마.

강한 능력을 없애거나 새로운 사용 횟수·준비시간·약점·상대의 간파 능력으로 전투를 늘리지 마. 사용하면 해결되는 상황에서 이유 없이 능력을 쓰지 않게 하지 마. 사용하지 않는 선택이 필요하면 목표·가치관·상황에 따른 이유를 앞에서 보여줘. 원전에 실제로 확인된 한계와 제작 편의를 위해 추가한 제한을 구분해.

확인되지 않은 능력치·승률·무적·유일한 약점을 만들지 마. 실제 원전 주장에만 읽은 본문 URL·위치·판본을 연결하고 창작은 기존 출처 기록에서 `hypothetical`로 구분해. 자료가 없으면 확인되지 않았다고 남기고 해당 주장을 삭제·수정해.

### 결말과 그림을 사건에 맞게 계획해

해피엔딩·화해·교훈을 의무로 두지 마. 승리·패배·부분 성공·손실·희생·비극·씁쓸한 결과 등 사건과 선택에 맞게 마무리해. 미리 정한 감정을 만들려고 능력과 성격을 뒤틀지 마. 전투 승리와 목표 달성의 차이가 있다면 사건 안에서 납득시켜.

중심 사건의 결과를 댓글이나 다음 편으로 떠넘기지 마. 사용자가 연작·열린 결말을 명시한 경우만 해결한 부분과 남긴 부분을 구분해. 처음의 성공 조건을 결말에서 다른 조건으로 몰래 바꾸지 마. 후일담은 결과를 이해시키는 만큼만 쓰고 승패·선택을 여러 번 해명하지 마.

마지막에는 실제 보여준 선택이나 결과를 묻고, `여러분의 생각을 댓글로 남겨 주세요.`를 정확히 한 번 읽어. 전체 낭독 대본에는 이를 포함해 보여주되, episode 본문 cue에 별도 중복 CTA를 넣지 말고 기존 공통 `cta` 연결 방식을 유지해.

대본의 행동을 먼저 정하고 자연스러운 카메라를 골라. 정면 얼굴을 고집하지 말고 측면·뒷모습·사선·어깨너머를 사용해. 손의 주인과 손목·팔꿈치·어깨, 다리·관절·무게중심, 물건을 잡고 받치는 동작, 무기의 끝부터 끝까지와 손 앞뒤 축·두께·위치를 실제 이미지 단계에서 확인할 수 있게 계획해. 자연스러운 가림을 허용하되 보이는 부분을 이었을 때 구조가 성립해야 해. 복장·체형·머리·무기·장비, 위치·경로·공격 방향·가림과 의도적인 상태 변화를 다음 컷에 연결해.

한 컷은 필요한 대표 순간이며 씬·컷·그림·자막 cue·낭독 그룹을 1:1로 강제하지 마. 이미지 수는 행동과 장면 변화에 맞춰 정하고 긴 정지 화면으로 시간을 채우지 마. 기존 자산은 재사용·수정·새 제작 여부와 이유를 연결하고 원본·이력은 보존해.

### 한 번에 검토 가능한 결과를 제출해

1. 위 아홉 항목을 포함한 전체 기획과 주요 전제, 선택 판본·관련 쇼츠 연결 판단.
2. 도입부터 결말·질문·댓글 안내까지 생략 없는 전체 낭독 대본. 사용자 검토안에는 결말도 공개해.
3. 씬별 사건 변화·예상 시간과 전투 구간 시작·종료·예상 합계, 공방별 행동·대응·실제 결과.
4. 이미지 연결표와 예상 제작량, 기존 자산의 재사용·수정·새 제작 여부와 이유.
5. 원전 근거·창작 부분·미확인 사항, [대본 검수표](longform_script_review.md)에 따른 실제 내용 관찰과 수정 사항.

예상값을 실측처럼, 파일 작성이나 형식 검사 성공을 내용·이미지·음성 PASS처럼 보고하지 마. 아직 생성·열람·검수하지 않은 것은 미실시로 밝혀.

## 승인 이후에 이어지는 순서

전체 대본·전제·예상 시간·공방표·이미지 연결표 제시 → 해당 범위 사용자 승인 → 이미지 전체 초안 생성 → 실제 등장 순서로 이미지 전용 검토 → 피드백 반영·수정·재검수 → 음성·자막·편집 → 최종 영상 검수.

같은 승인 범위의 개별 이미지 수정마다 다시 묻지 않는다. 이미지 전체 초안 선전달을 자동 수정 반복으로 지연하지 않되, 최종 사용 그림은 실제로 열고 문제를 고친 뒤 재검수한다. 기존 음성·시간표는 보존하고 변경 영향에 맞게 재사용하거나 갱신한다.

최종에는 실제 전체 길이, 전투 구간과 합계, 수정한 문제와 남은 문제를 보고한다. 음성의 ASR·누락·끝 잘림·음량·자막 동기 기술 검사와 사용자 전체 MP4 청취 승인을 구분한다. 최종 음성 PASS는 사용자가 전체 영상을 끝까지 듣고 승인한 뒤 확정하며 그전에는 `청취 승인 대기`다. 이 프롬프트 자체는 새 작품 제작·외부 업로드·게시 승인이 아니다.
