기존 대결 쇼츠 시스템에 ‘9~15분 서사형 대결 롱폼’의 공용 제작 시스템을 구축해.

이 명령은 특정 인물·대진·의뢰·질문·줄거리를 만드는 일회성 지시가 아니다.
앞으로 어떤 허용 인물이 선정되든 그 인물의 배경·성격·가치관·목적·능력·한계를 조사하고, 그 특성에서 새로운 가상 사건과 이야기를 자율적으로 구성하는 공통 운영 규칙이다.

특정 인물이나 과거에 예시로 든 이야기를 기본값으로 저장하지 마.
사용자가 매번 인물 둘·줄거리·중심 질문·결말을 모두 지정해야 작동하는 시스템으로 만들지 마.
아래 기획 항목은 사용자가 답해야 하는 질문지가 아니라, 네가 조사하고 판단하여 스스로 완성해야 하는 항목이다.

이번 요청에서는 공용 규칙·프로필·필요한 코드 연결과 관련 검증까지 반영해.
특정 작품을 예약하거나 실제 작품의 대본·이미지·음성·영상을 임의로 만들지 마.
반영 결과와 수행한 검사, 남은 제한을 보고한 뒤 종료해.
실제 롱폼 제작은 이후 제작 요청이 들어왔을 때 아래 공용 절차로 진행해.

━━━━━━━━━━━━━━━━━━━━━━━━
1. 기본 운영 원칙과 보존 범위
━━━━━━━━━━━━━━━━━━━━━━━━

- 현재 AGENTS.md, docs/production_rules.md, docs/automatic_planning.md와 실제 코드·작업 상태를 먼저 확인해.
- 이전 명령문이 있다는 이유만으로 해당 기능이 이미 구현됐다고 가정하지 마.
- 기존 쇼츠 시스템·기본값·저장된 프로필·완료 편·다른 진행 작업은 유지해.
- 롱폼은 별도 제작 모드로 추가하고, 공통 엔진·검수·저장·전달 기능을 재사용해.
- 롱폼 지원 때문에 쇼츠용 상수를 전역으로 바꾸거나 기존 에피소드를 일괄 변경하지 마.
- 기존 대진 금지 기준, 원전·판본 확인, 인물 전체 이름 표기, 외부 서비스 제한을 유지해.
- Gemini 사용 금지, 유료 서비스·새 계정·외부 전송에 관한 기존 승인 범위를 유지해.
- 실제 검수와 형식 검사, 자체 QA와 사용자 수락의 구분을 유지해.
- 롱폼의 최종 음성 승인에는 12절의 사용자 청취 기준을 적용해. 기존 쇼츠의 음성 검수 기준은 유지해.
- 기존 수정 한도·수정 이력·해시·재개·중복 방지·전달 검증을 유지해.
- 규칙은 실제 프로젝트 문서에 저장하고, 이후 작업 시작 시 읽고 적용하도록 연결해.
- 대화에서 ‘숙지했다’고 말하는 것만으로 시스템 반영을 완료했다고 보고하지 마.
- 특정 편의 장소·무기·결말·예외를 모든 편의 공통 규칙으로 승격하지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
2. 롱폼의 공통 제작 규격
━━━━━━━━━━━━━━━━━━━━━━━━

- 제작 형식: longform
- 프로필: showdown_story_long_v1
- 같은 프로필이 이미 있으면 현재 구현을 확인하고 필요한 내용을 보완해. 중복 프로필을 만들지 마.
- 최종 MP4 전체 실제 길이: 540~900초, 즉 9분 이상 15분 이하.
- 9분·11분·13분·15분 중 특정 길이를 강제하지 마. 사건에 필요한 길이를 범위 안에서 선택해.
- 시작·본문·결말·댓글 안내·전환을 모두 전체 길이에 포함해.
- 기본 화면: 가로 16:9, 1920×1080, 30fps.
- 영상·음성: 기존 H.264/yuv420p MP4, AAC 및 검증된 합성 기술 활용.
- 기본 표현: 기존 화풍의 정지 일러스트와 기존 화자 중심의 내레이션.
- 기본 BGM 없음, 줌·이동·흔들림 없음은 유지해.
- 중심 인물은 기본 두 명으로 하고, 조연은 사건에 필요한 역할만 맡겨.
- 무관한 제3의 강자나 군대가 등장해 중심 인물의 갈등을 대신 해결하는 구조로 만들지 마.
- 그림 수·화면 컷 수·자막 cue 수·공방 수·챕터 수는 이야기마다 정해.
- 쇼츠의 9장·14 cue·공방 2회·인물별 소개 2 cue·30~60초 제한을 롱폼에 적용하지 마.
- 롱폼의 기본은 한 편의 사건이 결과에 도달하는 이야기다. 쇼츠의 승부 직전 중단을 필수 결말로 적용하지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
3. 사용자 입력에 따른 자율 선정
━━━━━━━━━━━━━━━━━━━━━━━━

이후 실제 제작 요청을 받으면 사용자가 준 정보와 기존 기록을 바탕으로 다음처럼 처리해.

1) 인물 두 명을 지정한 경우

- 지정한 조합을 우선 검토해.
- 두 인물의 특성에서 사건·목표·갈등·결말을 구성해.
- 새로운 장소나 조건은 기획안에 명시하고, 이미 승인된 조건이라고 가정하지 마.

2) 인물 한 명만 지정한 경우

- 해당 인물의 판본·배경·능력을 확인해.
- 기존 선정 기준과 이력을 확인하고 적합한 상대를 자율적으로 선정해.
- 그 상대와 이야기가 성립하는 이유를 함께 제시해.

3) 주제·분위기·사건 유형만 지정한 경우

- 지정한 방향에 맞는 인물 조합과 사건을 함께 선정해.
- 지정하지 않은 줄거리·목표·결말은 네가 구성해.

4) ‘롱폼 한 편 만들어’처럼 구체적인 지정이 없는 경우

- 현재 진행 작업, 처리 가능한 롱폼 대기열, 후보·완료·거절 이력을 확인해.
- 기존 선택 순서와 사용자 의도를 따르되 적절한 후보가 없으면 새 조합을 조사해.
- 인물 조합과 새로운 이야기를 선정하고 전체 기획·대본까지 진행해.
- 사용자에게 인물·의뢰·장소·결말을 하나씩 정해 달라고 넘기지 마.

5) 사용자가 줄거리·조건·결말 일부를 지정한 경우

- 지정한 부분을 우선하고 나머지만 합리적으로 구성해.
- 서로 양립하지 않는 조건이나 중요한 근거 부족이 있으면 문제와 구체적인 대안을 설명해.
- 자료를 확인하면 해결할 수 있는 사항은 먼저 조사해.

6) ‘이어 해’, ‘수정해’, ‘새로 만들어’인 경우

- 기존 작업 ID·단계·승인 범위·변경 요청을 먼저 확인해.
- 재개·부분 수정·새 작품·명시적 재제작을 구분해.
- 이미 진행 중인 작품을 새 작업으로 중복 예약하지 마.

쇼츠와 롱폼은 현재 요청과 문맥으로 구분해.
문맥상 롱폼이 분명하면 반복해서 확인하지 마. 쇼츠의 기존 기본값은 유지해.
명확한 새 작품 요청이 없는데 기존 작품을 임의로 다른 인물이나 줄거리로 바꾸지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
4. 캐릭터 조사에서 이야기를 만들어 내는 방법
━━━━━━━━━━━━━━━━━━━━━━━━

이야기를 정해 놓고 인물 이름만 끼워 넣지 마.
아래 연결을 따라 인물의 특성이 사건의 원인이 되게 구성해.

배경·성격·가치관·능력·한계
→ 원하는 것과 지키려는 것
→ 상대와 목표가 부딪히는 이유
→ 그 인물다운 선택과 행동
→ 행동이 만든 결과와 새로운 문제
→ 다음 선택과 사건의 결말

인물별로 다음을 확인해.

- 정체, 출전, 사용할 판본과 시기.
- 살아온 배경이나 처지가 현재 행동에 주는 영향.
- 중요한 가치관과 행동 성향.
- 얻으려 하거나 지키려 할 만한 것.
- 확인된 능력·무기·기술·대표 활약.
- 확인된 한계와, 알 수 없어 단정할 수 없는 부분.
- 어떤 상황에서 강점과 성격이 잘 드러나는지.
- 상대의 특성이 이 인물에게 어떤 문제를 만드는지.

원전에 없는 욕망·감정·선택을 창작할 수는 있지만, 원전의 사실이라고 소개하지 마.
원전에 등장한 대표 활약은 능력 이해의 근거로 활용해. 매번 그 사건을 그대로 재연하는 데 그치지 마.
인물 조사 내용을 영상 앞에서 전부 읽지 말고, 현재 사건을 이해하는 데 필요한 부분을 적절한 시점에 사용해.

선정 단계에서는 원전 근거, 대진 이유, 인물 고유성, 사건의 완결성, 시각화 가능성, 기존 편과의 차이를 함께 판단해.
확인되지 않은 인지도나 자체 점수를 실제 인기·조회수 예측치로 말하지 마.

[기존 쇼츠를 조사 출발점으로 활용]

- 같은 인물 조합의 쇼츠가 있으면 source_records, character_bible, 해당 대본의 핵심 떡밥·마지막 질문·가상 전제를 먼저 읽어.
- 해당 이름의 파일이 없으면 실제 프로젝트의 대응 기록을 찾아. 없는 기록을 읽었다고 보고하지 마.
- 여러 편이 있으면 이번 판본과 사건에 적합한 편을 선택하고 연결할 작업 ID를 남겨.
- 선택 판본·시기·능력 해석·복장·외형 기준이 맞는지 확인해.
- 기존에 확인된 근거는 재사용하고, 새 주장·달라진 판본·불확실한 해석에 필요한 부분을 추가 조사해.
- 쇼츠에 등장했다는 이유만으로 사실이라고 간주하지 마. 창작 상황·약점·조건을 원전 설정으로 승격하지 마.
- 쇼츠의 마지막 질문이 이번 롱폼의 판본·전제·성공 조건과 자연스럽게 맞으면 중심 질문으로 이어받고 영상 안에서 답해.
- 맞지 않으면 새 질문을 만들고, 이어받지 않은 이유를 기존 기획 기록에 한두 문장으로 적어.
- 같은 질문 문장이라도 조건이 달라졌다면 같은 사건의 답처럼 포장하지 마.
- 쇼츠의 장면을 직접 이어가는 경우 기존 위치·소지품·능력 조건·목표를 확인하고 연속성을 지켜.
- 별개 사건을 만드는 경우에는 새 사건이라는 점이 드러나게 해.
- 관련 쇼츠가 없어도 롱폼을 제작할 수 있어. 쇼츠를 먼저 만들도록 강제하지 마.
- 쇼츠 원본·기록은 수정하지 마. 연결 정보와 추가 조사 결과는 롱폼의 기존 기록에 남겨.

━━━━━━━━━━━━━━━━━━━━━━━━
5. 매 작품에서 네가 스스로 완성할 기획 항목
━━━━━━━━━━━━━━━━━━━━━━━━

아래 항목은 사용자에게 입력을 요구하는 질문지가 아니다.
선정한 인물과 확인한 자료를 바탕으로 네가 정리하고, 완성된 기획안으로 제시해.

1) 중심 사건과 질문

- 이번 영상에서 시작해 끝까지 따라갈 사건을 정해.
- 그 사건에서 생기는 핵심 의문을 한 문장으로 정해.
- 질문을 항상 승패·명중·포획으로 고정하지 마.
- 제목·도입·본문·결말이 같은 관심사를 다루게 해.

2) 양쪽의 목표와 성공 조건

- 각 인물이 무엇을 얻거나 지키려 하는지 정해.
- 무엇을 달성하면 성공이고 무엇이 실패인지 구분해.
- 두 인물의 목표가 반드시 같을 필요는 없지만 서로 어떻게 영향을 주는지 명확해야 해.

3) 행동 동기와 이해관계

- 왜 이 인물이 지금 행동하는지, 왜 이 사건에 관여하는지 정해.
- 실패하면 무엇을 잃거나 어떤 문제가 생기는지 정해.
- 단순히 ‘의뢰를 받았다’거나 ‘상대가 나타났다’는 말로 동기를 대신하지 마.

4) 정보와 판단

- 각 인물이 아는 사실, 모르는 사실, 믿고 있는 정보를 정해.
- 새로운 정보가 들어오면 행동이 어떻게 달라지는지 연결해.
- 오해나 비밀이 필요하지 않은 이야기에는 억지로 만들지 마.

5) 장소와 상황

- 지형·출입구·이동 경로·위험 요소 중 사건에 필요한 것만 정해.
- 서로 다른 지역·시대의 인물이 만나는 것은 가상 세계의 전제로 설정할 수 있어.
- 실제 역사에서 만난 것처럼 꾸미지 마.

6) 능력과 상황적 제약

- 원전에서 확인한 능력·무기·한계와 창작한 사건 조건을 구분해.
- 현재 목표와 상황이 어떤 행동을 가능하게 하거나 어렵게 하는지 정해.
- 긴장감을 위해 능력을 갑자기 삭제하거나 새 약점을 만들지 마.

7) 사건의 진행과 선택

- 첫 행동이 어떤 결과를 낳는지 정해.
- 그 결과 때문에 어떤 새로운 선택이 필요한지 연결해.
- 같은 시도와 실패만 반복하지 마.

8) 사건의 결과

- 중심 질문에 이번 영상에서 어떤 결과로 답할지 정해.
- 인물이 목표를 바꾼다면 바꾸는 이유와 과정 자체를 보여줘.
- 제작한 사건의 결과와 원전의 공식 승패를 구분해.

9) 시각화·시간·제작량

- 필요한 씬·장소·조연·화면 컷·새 이미지·재사용 자산을 계획해.
- 9~15분 안에서 자연스러운 분량을 선택해.
- 그림으로 전달하기 어렵거나 제작량이 과도하면 먼저 사건과 구도를 단순화해.

━━━━━━━━━━━━━━━━━━━━━━━━
6. 사건 유형과 이야기의 다양성
━━━━━━━━━━━━━━━━━━━━━━━━

- 인물의 특성과 목표에 맞는 사건 유형을 매번 선택해.
- 의뢰·추적·탈출·보호·회수·경쟁·약속·가치관 충돌 등은 선택 가능한 유형이지 필수 구성 요소가 아니야.
- 모든 편을 의뢰로 시작하거나 한쪽이 다른 쪽을 쫓는 이야기로 만들지 마.
- 오해 해소, 숨은 악인, 공동의 적, 동맹 결말, 마지막 한 발 같은 전개를 고정 공식으로 사용하지 마.
- 인물의 배경과 개성에 따라 도입·갈등·장소의 역할·핵심 행동·해결 방식이 달라져야 해.
- 이름과 장소만 바꾸고 같은 줄거리를 반복하지 마.
- 기존 편들과 갈등 원인, 양쪽 목표, 주요 전술, 중요한 발견·선택, 해결 방법이 지나치게 겹치는지 확인해.
- 모든 요소가 매번 달라야 한다고 강제하지는 마. 같은 인물 조합도 새로운 사건을 만들 수 있고, 다른 조합도 같은 이야기를 반복할 수 있어.
- 서사 다양성을 인물 이름의 중복 여부만으로 판정하지 마.
- 새 이야기임을 설명하려고 근거 없는 능력·복잡한 조연·불필요한 반전을 추가하지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
7. 기본 뼈대와 사건의 인과관계
━━━━━━━━━━━━━━━━━━━━━━━━

아래를 기획의 기본 뼈대로 사용해.
이야기에 맞지 않으면 순서·배치·비중을 조정하고, 중요한 변경 이유를 기존 기획안에 한두 문장으로 적어.
기획 중 뼈대를 조정했다는 이유만으로 별도의 예외 승인이나 새 검수 파일을 요구하지 마.

1) 도입

- 첫 약 30초 안에 사건의 긴장된 순간·위기·핵심 의문을 보여주는 것을 편집 목표로 삼아.
- 관객이 무엇을 보게 될지 이해할 수 있어야 해.
- 맥락 없는 결전 장면이나 결말 미리보기를 매번 강제하지 마.

2) 인물 A의 이해

- 이번 사건의 행동을 이해하는 데 필요한 원전 활약·성격·능력만 짧게 소개해.

3) 인물 B의 이해

- 같은 기준으로 이번 사건과 관련된 부분만 소개해.

4) 사건 발단

- 두 인물이 원하는 것과 그 목표가 부딪히는 이유를 드러내.

5) 첫 충돌

- 한쪽의 행동과 상대의 대응이 실제 상황을 바꾸게 해.
- 누가 어떤 점에서 유리하거나 불리해졌는지, 무엇을 얻거나 잃었는지 보여줘.
- 반드시 완승·제압으로 끝낼 필요는 없어.

6) 변화

- 앞선 행동의 결과, 새 정보, 인물의 선택 때문에 상황이 달라지게 해.
- 같은 시도를 반복하지 말고 다음 행동의 이유를 만들어.

7) 결정적 충돌

- 앞에서 제시한 능력·조건·단서·선택이 결정적인 행동으로 이어지게 해.
- 두 인물의 대응이 이번 사건의 결과에 어떻게 작용하는지 보여줘.

8) 결말과 마지막 질문

- 시작에서 제시한 중심 질문에 이번 사건의 결과로 답해.
- 그 결과나 선택을 바탕으로 시청자의 의견을 물어.

[A·B 소개의 배치]

- 2·3번은 고정된 독립 챕터가 아니야.
- 두 인물을 앞에서 연속 소개하는 것이 가장 명료하면 짧게 사용해.
- 소개 때문에 사건이 멈추면 관련 행동 직전·직후에 나누어 배치하거나 사건 속에 섞어.
- 관련 원전 활약이 확인되지 않으면 만들어 넣지 말고 확인 가능한 특성만 사용해.
- 두 인물의 소개 시간을 똑같이 맞추거나 긴 전기를 낭독하지 마.

[두 인물의 역할]

- 두 인물 모두 확인된 능력·성격이 드러나는 행동이나 선택으로 사건에 실제 영향을 주어야 해.
- 한쪽을 수동적인 과녁이나 상대 설명용 인물로 만들지 마.
- 양쪽의 우세가 자연스럽게 바뀌는 전개는 사용할 수 있어.
- 반드시 한 번씩 우세하게 만들거나, 능력 격차를 지워 대등하게 맞추지는 마.
- 유리함은 공격 성공뿐 아니라 위치 확보·정보 획득·보호·도주·목표 달성 등 이번 사건의 목적에 맞게 보여줄 수 있어.
- 우세를 교대시키려고 갑작스러운 약점·실수·능력 제한을 만들지 마.

[인과관계와 분량]

- 첫 화면부터 이야기의 사건이나 관심사를 보여줘.
- 도입의 약 30초는 편집 목표이며 흥행 공식이나 기계적 합격선이 아니야.
- 긴 인사·채널 소개·인물 전기 나열로 사건 시작을 미루지 마.
- 원전 활약 설명과 회상은 현재 사건을 이해하는 데 필요할 때 사용해.
- 회상과 현재를 구분하고, 돌아온 뒤 현재 위치·목표가 명확해야 해.
- 장면마다 정보·목표·위험·위치·관계·소지품·선택지 중 필요한 변화가 있어야 해.
- 앞 장면의 결과가 다음 장면의 이유가 되어야 해.
- 한마디로 해결될 문제를 특별한 이유 없이 오래 끌지 마.
- 우연한 구원자나 갑자기 생긴 능력·약점으로 결말을 해결하지 마.
- 결정적인 대응과 결말에 필요한 단서는 미리 제시해.
- 관객이 알아야 할 위치·조건을 숨겨 생긴 혼란을 반전으로 포장하지 마.
- 반복 설명, 같은 공방, 불필요한 우회, 긴 무음으로 시간을 채우지 마.
- 본문에 없는 장면이나 끝내 답하지 않을 질문을 제목·썸네일로 약속하지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
8. 원전과 창작의 공통 경계
━━━━━━━━━━━━━━━━━━━━━━━━

[확인된 근거가 필요한 것]

- 원전의 사실로 소개하는 정체·배경·성격·대표 활약.
- 능력·무기·기술과 중요한 한계.
- 승부에 영향을 주는 발동·해제 조건·효과 범위.

[새 이야기로 구성할 수 있는 것]

- 만남·사건·장소·상황·의뢰·갈등.
- 이번 사건에서의 목표·선택·대사·전술.
- 설정한 조건 안에서 벌어지는 행동과 그 결과.

[적용 규칙]

- 원전의 인물 설정과 이번 영상에서 창작한 사건을 명확히 구분해.
- 서로 다른 판본에서 유리한 능력만 가져와 합치지 마.
- 실존 인물과 그를 모델로 만든 소설·희곡 인물의 설정을 섞지 마.
- 새 대사를 원전의 실제 발언처럼 인용하지 마.
- 자료가 없으면 확인되지 않았다고 남기고, 필요한 주장은 삭제하거나 확인 가능한 내용으로 바꿔.
- 강한 능력으로 사건을 바로 해결할 수 있다면 그 가능성을 검토해.
- 사용하지 않는 이유가 필요하면 인물의 목표·보호 대상·상황·선택과 연결하고 앞에서 제시해.
- 능력 고장, 갑작스러운 사용 횟수 제한, 설명되지 않은 무효화 같은 편의적 제약을 만들지 마.
- 원전에 없는 물리적 성질이나 약점을 사실처럼 추론하지 마.
- 새로운 사건 조건은 기획안과 대본에서 밝혀 일관되게 적용해.
- 처음의 성공 조건을 결말에서 다른 조건으로 몰래 바꾸지 마.
- 창작 결과를 공식 승패·객관적인 강함 순위·실제 역사라고 주장하지 마.
- 초반의 자연스러운 표현과 영상 설명에서 원전 인물 설정을 활용한 가상 이야기임을 밝혀.

출처 기록은 기존 sources.md와 source_records.json 등을 활용해.
실제 원전 주장에는 읽은 본문 URL·위치·판본과 문장을 연결해.
창작 장면은 hypothetical로 구분하고, 존재하지 않는 출처를 억지로 붙이지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
9. 문체·대사·구체적인 행동
━━━━━━━━━━━━━━━━━━━━━━━━

- 기본은 기존 화자의 자연스러운 내레이션으로 해.
- 직접 대사는 인물의 선택·감정·대립을 보여주는 데 필요한 순간에 사용해.
- 같은 화자가 읽어도 누가 말하는지 이해되게 작성해.
- 다인 성우·새 음성 서비스는 기본 필수 기능으로 추가하지 마.
- 짧고 명확한 구어체를 쓰고 낯선 이름·지명·설정을 한꺼번에 쏟아내지 마.
- 긴 수식과 감정 설명, 같은 정보의 반복으로 분량을 채우지 마.
- 배경 묘사는 위치·위험·선택을 이해하는 데 필요한 만큼 사용해.
- 임의의 능력치·승률·무적·유일한 약점을 만들지 마.

각 공방이나 연결된 행동 묶음에서 다음이 이해되어야 해.

누가 / 무엇을 이용해 / 무엇을 대상으로 / 어떻게 행동했고 / 무엇이 달라졌는지

- 모든 자막 cue마다 다섯 요소를 반복하지 마.
- 직전 맥락에서 분명한 주어·도구·대상은 자연스럽게 생략할 수 있어.
- 관찰·판단은 무엇을 보고 알아냈으며 다음 행동이 어떻게 달라지는지 확인해.
- ‘몰아붙인다·빈틈을 노린다·압도한다·맞선다·격돌한다·반격한다’만으로 공방을 설명하지 마.
- 이런 표현이 있더라도 구체적인 행동과 결과가 맥락에 있어야 해.
- 단어 경고는 보조 검사로 사용하고, 경고가 없다는 이유로 좋은 대본이라고 판정하지 마.
- 접속어의 반복보다 실제 원인과 결과의 연결을 확인해.
- 특정 인물의 개성이 드러나지 않는 일반적인 공격·방어만 나열하지 마.

━━━━━━━━━━━━━━━━━━━━━━━━
10. 씬·그림·자막·음성의 단위와 연속성
━━━━━━━━━━━━━━━━━━━━━━━━

다음 네 단위를 구분하고 1:1로 강제하지 마.

- 씬: 장소·시간·주요 목표가 이어지는 이야기 단위.
- 화면 컷: 정지 그림으로 보여주는 대표 순간.
- 자막 cue: 한 번에 표시하는 자막 단위.
- 낭독 그룹: 자연스럽게 이어 읽는 문장 묶음.

한 씬에 여러 컷이 있을 수 있고, 한 컷에서 자막은 여러 번 바뀔 수 있어.
그림이 바뀌어도 같은 문장의 낭독이 이어질 수 있어.
자막을 나눴다는 이유로 그림이나 TTS 요청을 하나씩 추가하지 마.

기존 storyboard와 관련 데이터에 아래를 연결해.

- 안정적인 씬·컷·cue·낭독 그룹 ID.
- 인물·장소·목표·방해·행동·결과·다음 씬의 이유.
- 컷별 이미지와 핵심 순간, 관련 cue.
- 원전 근거와 창작 구분.
- 다음 장면에 영향을 주는 상태 변화.

연속성 확인 대상:

- 위치·이동 방향·공격 방향.
- 무기·도구·짐 등 중요한 소지품.
- 문·담·통로·장애물 등 장소의 구조.
- 부상·피로·손상 등 행동에 영향을 주는 상태.
- 각 인물이 알고 있는 정보.
- 능력의 확인된 조건과 사건의 제약.

모든 상태를 매 cue에 복사하는 복잡한 시스템을 만들지 마.
장면 삽입 때문에 기존 ID가 전부 바뀌어 재사용이 무효화되지 않게 해.

━━━━━━━━━━━━━━━━━━━━━━━━
11. 그림·편집·썸네일의 공통 규칙
━━━━━━━━━━━━━━━━━━━━━━━━

- 인물 기준과 화풍을 재사용하되 이번 판본·시기·복장에 맞는지 확인해.
- 기존 쇼츠의 원본 자산을 수정하지 마.
- 가로 화면에 맞게 장면을 구성하고, 세로 그림을 가로로 늘여 인체를 변형하지 마.
- 각 그림은 핵심 순간 하나를 보여줘.
- 연결된 대본은 그 순간의 짧은 원인과 직접 결과를 설명할 수 있어.
- 여러 장소·여러 단계의 행동을 한 정지 그림에 모두 담으라고 요구하지 마.
- 대사에서 행동 상태가 크게 바뀌면 화면도 그 변화를 전달해야 해.
- 전체 구도로 위치를 설명하고 필요한 순간에는 손·무기·시선·단서의 근접 구도를 사용해.
- 모든 컷에 두 인물의 전신을 강제하지 마. 누구의 행동인지와 앞뒤 관계는 명확해야 해.
- 기존 신체·손·관절·무기·접점·복장·기마·크롭 검수 기준을 유지하고, 아래 실제 시각 검수·수정·재검수 절차를 적용해.
- 피·절단·잔혹한 부상은 넣지 마.
- 원본 이미지 수와 화면 컷 수를 구분해.
- 같은 그림은 인물·장소·무기·상태가 맞을 때만 재사용해.
- 긴 정지 구간은 유지시간과 이유를 확인해. 말로 여러 사건이 진행되는데 화면이 그대로인 구간을 줄여.
- 일정 초마다 무조건 그림을 바꾸거나 고정 그림 수를 채우지 마.
- 생성 전에 예상 새 이미지 수·재사용 수·컷 수를 제시해.
- 제작량이 과도하면 먼저 장소·조연·구도를 단순화해.

[생성 전 동작·접점 설계]

- 주요 행동 컷은 누가 어느 손으로 무엇을 잡고, 어디를 향해 움직이며, 상대가 어떻게 반응하는지 정해.
- 몸의 방향·손과 무기의 접점·발과 지면의 관계·인물 간 거리가 그 순간의 행동과 맞는지 먼저 확인해.
- 인물 기준 이미지와 해당 무기·복장 자료를 활용하고, 불필요하게 복잡한 손짓·겹침·원근은 줄여.
- 대본의 핵심 행동이 잘 보이는 구도를 선택해. 확인하기 어려운 자세를 프롬프트 문구만으로 해결됐다고 간주하지 마.

[원본 이미지의 실제 시각 검수]

- 새로 생성하거나 수정한 모든 이미지를 실제로 열어 전체 구도부터 확인해.
- 손가락·손목·관절·다리·발·얼굴·무기와 접점 등 필요한 부위를 확대해서 확인해.
- 작은 미리보기나 여러 컷을 작게 모은 화면만 보고 세부 검수를 끝내지 마.
- 생성 성공 메시지·프롬프트·파일명·해상도·해시 확인은 시각 검수를 대신하지 못해.

확인할 항목:

- 손·손가락: 인물 설정에 없는 손가락 추가·융합·분리, 어색한 길이와 꺾임, 엄지 위치, 손목 연결을 확인해.
- 팔·관절: 어깨→팔꿈치→손목→손의 연결과 길이·방향을 확인해. 겹친 두 인물의 팔이 합쳐지거나 다른 인물의 손처럼 이어지지 않아야 해.
- 다리·발: 골반→무릎→발목→발의 연결, 발 방향, 다리의 추가·소실·비정상 꺾임을 확인해. 서기·달리기·점프 등 해당 순간에 맞는 균형과 지지 관계를 확인해.
- 얼굴·몸통: 얼굴과 목·어깨 연결, 시선·머리·몸통 방향, 인물의 비율이 자세와 화풍 안에서 자연스러운지 확인해.
- 무기·소품: 손잡이·칼날·창대·활·시위·화살 등 해당 도구의 구조와 연결이 유지되는지 확인해. 이유 없이 휘거나 끊어지거나 두 개로 늘어나거나 다른 물체와 합쳐지지 않아야 해.
- 손과 무기의 접점: 의도한 사용법에 맞게 잡고 있는지, 손과 무기의 각도·크기·지지가 자연스러운지 확인해. 의도하지 않은 공중 부양이나 손·몸을 관통하는 형태를 통과시키지 마.
- 인물 간 행동: 공격·방어·회피의 방향과 거리, 접촉 위치가 대본과 맞는지 확인해. 무기가 닿지 않았는데 막은 것으로 보이거나 다른 인물의 신체와 섞이지 않아야 해.
- 장면 연속성: 무기 종류·형태·소지품·복장·손상·잡는 손이 이유 없이 바뀌지 않는지 확인해. 화면의 좌우와 인물의 실제 왼손·오른손은 구분해.

[가림·원근·화풍의 판단]

- 손가락 다섯 개나 양쪽 발이 항상 모두 보여야 한다고 강제하지 마.
- 주먹·장갑·몸·무기·화면 경계 때문에 자연스럽게 가려진 부위를 곧바로 누락으로 판정하지 마.
- 원근에 따른 크기 차이, 만화적 과장, 공중 동작은 해당 화풍·설정·행동에 맞으면 허용해.
- 보이는 범위의 구조와 연결은 설명 가능해야 해. 명확한 인체·접점 오류를 단순히 화풍이라고 처리하지 마.

[최종 합성 화면 검수]

- 원본 검수 뒤 실제 1920×1080 영상의 각 컷에서 합성된 프레임을 확인해.
- 크롭·배치·자막이 적용된 상태에서 그 컷의 핵심 손동작·무기 접점·자세가 읽히는지 확인해.
- 자막과 크롭으로 결함을 가려 놓고 수정했다고 보고하지 마. 자연스러운 근접 구도는 허용하되 필요한 행동 정보는 유지해.
- 같은 원본을 다른 크롭·배치로 사용한 컷은 실제 사용 화면도 확인해.
- 전환이 있는 경우 시작·중간·끝의 필요한 프레임에서 얼굴·손·무기가 어색하게 겹치거나 잘리지 않는지 확인해.
- 전체 MP4 디코딩 성공을 시각 검수 PASS로 대신하지 마. 모든 프레임을 사람이 봤다고 과장하지 말고 실제로 확인한 컷과 전환을 기록해.

[오류 발견·수정·재검수]

- 오류가 있으면 이미지·컷 ID, 문제 위치, 잘못된 연결이나 동작을 구체적으로 적어.
- 기존 승인 범위와 수정 한도 안에서 문제 이미지만 편집하거나 재생성해. 그림마다 사용자에게 다시 허락을 묻지 마.
- 수정 후 문제 부위만 보지 말고 원본 전체를 다시 확인해. 손을 고치면서 무기·팔·얼굴·복장이 달라졌는지도 확인해.
- 같은 이미지를 사용한 컷과 영향을 받은 인접 컷의 연속성·합성 화면을 다시 확인해.
- 기준 인물 디자인 자체가 달라졌다면 영향을 받은 다른 이미지까지 확인해.
- 복잡한 자세가 반복 실패하면 대본의 핵심 행동을 유지하면서 카메라·자세·무기 각도를 단순화해.
- 주요 행동·전제·결말까지 바꾸는 수정이 필요하면 그 변경을 구체적으로 제시해.
- 기존 수정 횟수와 이력을 유지해. 파일명·컷 ID를 바꿔 수정 한도를 초기화하지 마.
- 실제로 볼 수 없거나 한도 안에서 결함을 해결하지 못하면 미검수·수정 필요 사유를 남기고 NEEDS_REVIEW로 보고해. 완료나 PASS로 바꾸지 마.
- 사용자 청취 승인은 남아 있는 그림 오류를 면제하지 않아.
- 그림만 수정하고 최종 오디오와 시간 배치가 같다면 12절에 따라 기존 청취 승인을 유지하고 필요한 화면·기술 검수만 갱신해.

[검수 근거와 재사용]

- 기존 이미지 검수 기록·qa_report·manifest에 이미지·컷 ID, 현재 해시, 실제 관찰, 결함 위치, 수정 내용, 재검수 결과를 연결해.
- ‘자연스러움 PASS’만 반복하지 말고 손·다리·무기·접점 중 실제로 확인한 핵심 내용을 짧게 기록해.
- 확대 화면·검수용 프레임은 기존 검수 경로를 활용하고, 같은 내용을 담은 별도 검수 문서를 늘리지 마.
- 동일 해시의 원본에 유효한 실제 검수 기록이 있으면 재사용할 수 있어. 이번 사건의 상태와 최종 합성 화면에 맞는지는 별도로 확인해.
- 이전에 사용했다는 사실이나 사람이 언젠가 승인했다는 추측만으로 통과시키지 마.

[편집·자막]

- 기존 정지 그림과 전환 기술을 활용하고 행동의 연속성과 장소·시간 변화를 구분해.
- cue만 바뀌면 그림 전환을 다시 적용하지 마.
- 세로 영상의 사진·자막 좌표를 가로 영상에 복사하지 마.
- 실제 가로 화면의 여백·글꼴·자막 최대 2줄·가독성을 확인해.
- 자막은 어절·의미 경계에서 나누고 작은 글씨로 억지로 밀어 넣지 마.
- 쇼츠의 글자 제한을 긴 낭독 문단 전체에 적용하지 마.

[썸네일]

- 롱폼 썸네일과 영상 첫 장면은 별도 용도로 관리해.
- 영상 시작에 VS 표지를 의무적으로 오래 보여주지 마.
- 인물과 이야기의 핵심 위기·의문을 드러내는 구도로 만들어.
- 쇼츠의 ‘이름·VS만 허용’을 롱폼에 강제하지 마.
- 추가 문구는 짧고 읽기 쉽게 쓰고, 본문에 없는 장면·결과를 약속하지 마.
- 가로 원본과 작은 목록 크기에서 글자·얼굴·주요 행동을 검수해.

12. 음성·시간표·실제 9~15분 검증

- 기존 TTS 엔진·화자를 우선 사용하고 실제 지원 여부를 확인해.
- 영상 전체를 한 TTS 요청으로 만들거나 cue마다 따로 생성하지 마.
- 자연스러운 문단·의미 단위와 엔진 한도에 맞춰 그룹을 구성해.

- 전체 시간표에서 화면 자막과 하나의 최종 SRT를 만들어 마지막 발화까지 대응시켜.
- 실제 청취·모델 음향 검수·ASR·기술 측정의 차이를 유지해. 전사 일치를 자연스러운 억양의 증거로 바꾸지 마.

[롱폼의 음성 검수와 사용자 청취 승인]

- 롱폼의 최종 음성 PASS는 사용자가 최종 MP4를 끝까지 듣고 승인한 것으로 해.
- Codex의 기술 검사 통과와 사용자의 청취 승인을 분리해서 기록해.
- 로컬 오디오 모델의 설치·실행·PASS는 롱폼의 필수 단계나 완료 조건이 아니야.
- 모델을 선택적으로 사용하더라도 사용자 청취 승인을 대체하지 마.
- 기존 쇼츠의 로컬 모델·음성 검수 규칙을 전역으로 변경하지 마.

Codex가 먼저 수행할 기술 검사:

- 실제 음성의 ASR 전사와 승인 대본을 대조해 누락·중복·순서·오독 의심 구간을 확인해.
- TTS 원본·PCM·최종 MP4의 시작과 끝, 마지막 발화, 그룹 연결부를 확인해 끝 잘림·누락 가능성을 검사해.
- 음량·클리핑·비정상 무음·오디오 규격·재생 시간과 기존 동기화 기준을 검사해.
- 음성·화면 자막·최종 SRT가 같은 발화를 같은 순서로 가리키는지 확인해.
- 발견한 오류는 기존 수정 한도 안에서 먼저 수정해.
- ASR·신호·타이밍 검사만으로 발음·억양·자연스러움이나 모든 끝 잘림을 확정적으로 검증했다고 주장하지 마.
- 실제 실행하지 못한 필수 기술 검사는 NOT_RUN 또는 기존 대응 상태로 남기고 이유를 적어. 사용자 청취로 이를 자동 면제하지 마.

검수용 전달과 상태:

- Codex의 필요한 기술·화면 검사가 끝나면 사용자가 확인할 최종 MP4·자막·검수 요약을 먼저 검수용으로 전달해.
- 검수용 전달에 COMPLETE나 사용자 청취 완료를 선행 조건으로 요구하지 마.
- 이때 기술 검사 결과와 함께 ‘청취 승인 대기’라고 보고해.
- 기존 NEEDS_REVIEW 상태에 해당 사유를 기록하고، queue에서 done으로 옮기지 마.
- 로컬 오디오 모델을 쓰지 않은 것은 그 자체로 실패 사유가 아니야.
- 사용자 청취가 남아 있다는 이유로 통과한 음성을 반복 생성하지 마.

승인 기록과 변경:

- 대본·전제 승인은 제작 진행 승인이고, 최종 MP4 청취 승인은 별도 단계야.
- 사용자가 해당 검수본을 끝까지 듣고 승인했다는 취지가 명확하면 인정해. 특정 승인 문구를 다시 요구하지 마.
- 단순 파일 수령·대본 승인·일부 구간 감상만으로 전체 청취 승인을 기록하지 마.
- 승인 대상 MP4와 오디오의 버전·해시, 승인 내용과 범위를 기존 검수·manifest 기록에 연결해.
- Codex가 직접 들은 것처럼 기록하지 마. 사용자 청취 승인을 다른 품질 항목의 면제로 확대하지 마.
- 승인 뒤 음성 내용·순서·발음·속도·음량·쉼·재생 시간 배치가 달라지면 새 검수본에 대한 청취 승인을 받아.
- 그림·자막·메타데이터만 바뀌고 최종 오디오와 시간 배치의 동일성이 확인되면 기존 청취 승인을 유지하고 영향을 받은 검수만 갱신해.
- 사용자 청취 승인과 나머지 제작·기술·화면·길이·전달 기준을 모두 충족한 뒤 COMPLETE와 done을 기록해.

[대본 단계의 시간]

- 총 글자 수를 고정된 정답으로 정하지 마.
- 같은 화자·속도의 검증된 기존 샘플이 있으면 발화량과 시간을 참고해.
- 참고 조건·추정 방법을 밝히고 쉼을 중복 계산하지 마.
- 근거가 없으면 씬별 시간을 편집 계획으로 제시해.
- 계획·추정과 실측을 구분해. 대본 승인 전 시간 추정을 위해 새 TTS를 호출하지 마.

[제작 단계의 시간]

- 실제 음성과 최종 편집 결과로 전체 540~900초를 검사해.
- 짧으면 필요한 사건·선택·결과 설명이 부족한지 확인해.
- 길면 중복·불필요한 우회·반복을 줄여.
- 과속·늘인 음성·긴 무음·의미 없는 정지 화면으로 맞추지 마.
- 승인된 사건 안의 문장·호흡·중복 조정은 진행해.
- 주요 사건·능력 해석·전제·결말을 새로 바꿔야 하면 그 추가 변경을 구체적으로 제시해.
- 실제 길이가 범위 밖이면 보고 문구만 바꿔 통과시키지 마.

13. 결말·CTA·제목·설명·전달
━━━━━━━━━━━━━━━━━━━━━━━━

[결말]

- 기본은 이번 사건의 중심 질문에 영상 안에서 답하는 것이다.
- 해당 이야기의 성공·실패·탈출·회수·선택·관계 변화 등을 보여줄 수 있어.
- 사건의 결과와 두 인물의 절대적인 강함을 구분해.
- 처음 약속한 목표를 다른 목표의 성공으로 몰래 대체하지 마.
- 목표가 바뀌는 전개라면 그 변화의 원인과 선택을 보여줘.
- 핵심 사건을 해결하지 않은 채 댓글로 결말을 정하라고 떠넘기지 마.
- 사용자가 연작·열린 결말을 명시하면 해당 형식으로 구성하고 이번 편에서 해결한 것과 남긴 것을 구분해.
- 마지막 질문은 본문에서 확인한 행동·선택·조건·결과에 대한 의견을 물어.
- 롱폼의 서사 결과를 지원하고, 쇼츠의 winner: "none"·승자 미공개 검사를 자동 적용하지 마.
- 기존 winner 필드가 필요하면 그 의미를 확인하고 롱폼의 사건 결과와 구분해. 쇼츠 동작은 유지해.

[CTA]

- 이야기와 마지막 질문 뒤 ‘여러분의 생각을 댓글로 남겨 주세요.’를 정확히 한 번 읽어.
- 좋아요·구독 요청은 기존처럼 화면으로만 표시해.
- 중간마다 댓글·구독 요청을 반복하지 마.
- 마지막 그림을 실제 발화 길이만큼 유지하고 긴 고정 CTA로 분량을 채우지 마.

[메타데이터·출력]

- 롱폼 제목은 영상이 실제로 답하는 중심 질문을 짧게 쓴 것으로 해.
- 누구의 어떤 사건인지 알아볼 수 있게 하고, 대본의 목표·성공 조건과 제목의 질문을 일치시켜.
- 제목·썸네일 문구·대본·자막·설명·댓글의 맞춤법을 확인해.
- 화살 등을 목표나 과녁에 명중시킨다는 뜻은 ‘맞히다’로 써. 시간·규격을 일치시킨다는 뜻의 ‘맞추다’와 구분해.
- 롱폼에 #쇼츠나 쇼츠의 태그 순서를 강제하지 마.
- 설명에는 선택 판본·확인한 출처·가상 창작이라는 설명·실제 사용한 AI 이미지와 합성 음성을 적어.
- 제목·썸네일·대본·설명·댓글이 같은 사건과 조건을 말해야 해.
- 챕터 타임스탬프는 실제 최종 시간표에서 만들어.
- 고정 댓글은 초안만 작성하고 명시적 요청 없이 게시하지 마.
- 영상·SRT·썸네일·제목·설명·댓글·출처·QA·manifest의 기존 전달 체계를 활용해.
- OS가 확인한 실제 바탕화면과 최종 제목 폴더 규칙을 유지해.
- 형식과 작업 ID로 출력을 구분하고 기존 쇼츠·다른 롱폼 파일을 덮어쓰지 마.
- 청취 승인 전 검수용 전달과 승인 후 최종 완료·전달 확정을 구분해. 승인된 영상을 이유 없이 다시 생성하지 마.

[쇼츠 연결 댓글]

- 실제로 연결할 같은 인물 조합의 쇼츠가 있으면, 롱폼 최종 완료 시 해당 쇼츠용 고정 댓글 초안을 하나 더 제공해.
- 기본 문구: ‘이 대결의 전체 이야기는 롱폼에서 확인하세요. [롱폼 영상 링크]’
- 해당 쇼츠의 질문·사건을 이어받은 경우에는 기본 문구를 사용해.
- 같은 인물 조합의 별개 사건이라면 ‘이 두 인물의 새로운 이야기는 롱폼에서 확인하세요. [롱폼 영상 링크]’처럼 실제 관계에 맞게 바꿔.
- 게시 주소가 없으면 링크 자리를 표시하고, 존재하지 않는 URL을 만들지 마.
- 연결할 쇼츠 ID와 댓글 초안은 롱폼의 기존 전달 자료에 넣고 쇼츠 원본·기록은 수정하지 마.
- 실제 댓글 게시·고정·기존 댓글 수정은 명시적 요청 없이 실행하지 마.

14. 문서·코드·중복·검수 연결
━━━━━━━━━━━━━━━━━━━━━━━━

[문서와 코드]

- 공용 롱폼 규칙은 docs/longform_production_rules.md에 정리해.
- AGENTS.md에는 형식 구분과 참조를 두고 상세 규칙을 중복 복사하지 마.
- 기존 production_rules.md와 automatic_planning.md의 공통 규칙·쇼츠 전용 규칙·롱폼 규칙을 구분해.
- 특정 작품 정보는 해당 작품 기록에 두고 공용 문서의 기본값으로 넣지 마.
- 프로필 선택부터 기획·cue·그림·음성·타임라인·렌더·검수·전달까지 실제 연결을 확인해.
- 이미지의 실제 검수 기록을 현재 이미지·컷·해시에 연결하고, 수정한 이미지가 예전 PASS를 그대로 물려받지 않게 해.
- 고정 컷 수·60초 상한·세로 좌표·조건 비교·승자 미공개·첫 프레임 썸네일·태그 등 쇼츠 전용 가정을 확인해.
- 롱폼에는 기술 검사 결과와 사용자 청취 승인 상태가 별도로 연결되게 해.
- 기존 코드가 로컬 오디오 모델 PASS를 필수로 요구하면 롱폼 프로필에서만 새 승인 기준을 적용해.
- 기존 전달 코드가 COMPLETE 이전의 파일 전달을 막으면 롱폼 검수본을 전달하는 경로를 최소한으로 추가해.
- 검수본 전달 기능 때문에 일반 완료 검사를 생략하거나 기술 실패를 PASS로 바꾸지 마.
- 기존 schema를 활용할 수 있으면 활용하고, 필요한 확장은 롱폼에 필요한 최소 범위로 해.
- 지원하지 않는 경로에서 쇼츠·구형 프로필로 조용히 내려가지 마.
- 기존 엔진을 재사용하고 전체 재작성이나 관계없는 리팩터링을 하지 마.

[중복과 재개]

- 동일 인물 조합의 쇼츠와 롱폼은 별도 제작물로 관리해.
- 쇼츠가 이미 있다는 이유로 새 롱폼을 건너뛰거나 쇼츠를 --remake하지 마.
- 형식·정규화한 인물 조합·서사/작업 ID를 구분해.
- 같은 롱폼 재실행은 기존 작업을 재개해.
- 같은 인물 조합의 새 사건을 요청받은 경우에는 실제 서사 차이를 확인해 별도 작품으로 관리할 수 있어.
- 제목만 바꿔 같은 작품을 중복 예약하거나 완료 이력을 지우지 마.
- 기존 잠금·queue/done·실패·검수대기·완료 이력을 유지해.

[검수와 수정]

- 동기·정보·능력·인과관계·단서·상태·성공 조건·결말·반복 여부를 검토해.
- 새로 쓰거나 수정한 모든 이미지와 최종 화면을 11절에 따라 실제로 확인해. 인체·무기·접점의 미해결 오류나 미검수 상태가 남으면 시각 검수 PASS로 처리하지 마.
- 모든 cue의 음성·화면 자막·SRT 대응과 씬·그룹 연결부, 시작·끝·마지막 음절을 확인해.
- 최종 MP4 전체를 디코딩해 손상·누락·규격·오디오·전체 길이를 확인해.
- 일부 구간만 확인하고 전체 검수 완료라고 보고하지 마.
- 긴 영상이라는 이유로 동기화 허용오차를 임의로 늘리지 마.
- 수정된 자산과 영향을 받은 시간표·자막·영상·검수를 갱신하고, 검증된 동일 입력은 재사용해.
- 재사용해도 최종 전체 결과의 길이·누락·연결 검사는 수행해.
- 기존 storyboard·sources·voice_plan·timeline·review·qa_report·manifest·revisions를 활용하고 중복 기록 파일을 늘리지 마.
- Codex의 실제 검사와 사용자의 청취 승인을 각각 수행 주체에 맞게 기록해.
- 실제로 확인하지 않은 결과, 실행하지 않은 검사, 한도 소진을 PASS로 기록하지 마.
- 기술 검사 PASS·청취 승인 대기·최종 음성 PASS·전체 COMPLETE를 같은 상태로 취급하지 마.

[효율·성과]

- 생성 전 새 이미지 수·재사용 수·컷 수·낭독 그룹 수를 제시해.
- 실제 생성 횟수·재작업 이유·확인 가능한 작업시간을 기록해.
- 근거 없는 비용·시간·조회수 예측을 만들지 마.
- 실제 분석 자료가 제공되면 유입·클릭률·초반 유지율·시청 시간·구간 이탈·재시청·구독·댓글을 씬과 연결해 다음 기획에 활용해.
- 이 시스템 설정만으로 새 유료 서비스·계정 연결·자동 업로드·예약 작업을 추가하지 마.

15. 이후 개별 제작 요청을 처리하는 절차
━━━━━━━━━━━━━━━━━━━━━━━━

[새 롱폼 요청]

1) 최신 규칙·진행·후보·완료·거절 이력을 확인해.
2) 사용자 입력 범위에 맞춰 인물 조합과 판본을 선정해.
3) 캐릭터 배경과 특성에서 새로운 사건을 구성해.
4) 기획 아홉 항목과 전체 줄거리를 스스로 완성해.
5) 9~15분으로 계획한 전체 낭독 대본을 작성해.
6) 씬·컷·자막·낭독 그룹·원전 근거·가상 전제·예상 제작량을 연결해.
7) 전체 기획·대본·장면 계획을 한 번에 검토할 수 있게 제시해.
8) 유효한 제작 승인이 없으면 대본과 주요 전제 승인 단계에서 멈춰.
9) 제작 승인이 있으면 이미지·음성·영상을 만들고 필요한 기술·화면 검수와 수정을 진행해.
10) 확인 가능한 최종 MP4·자막·검수 요약을 검수용으로 전달하고 ‘청취 승인 대기’로 보고해.
11) 사용자가 해당 영상을 끝까지 듣고 승인하면 해당 버전의 음성 승인을 기록해.
12) 나머지 완료 기준과 전달 결과를 확인하고 COMPLETE·done을 반영해. 연결할 쇼츠가 있으면 추가 댓글 초안을 함께 전달해.

[승인과 재개]

- 기획 중 인물·장소·질문·결말을 하나씩 승인받으려 하지 마. 완성된 제안과 대본을 먼저 만들어.
- 이미 해당 대본과 전제에 유효한 승인이 있으면 다시 묻지 마.
- 문맥상 제작 진행 승인이 분명하면 특정 승인 단어를 다시 요구하지 마.
- 단순한 대본 이어쓰기 요청을 모든 제작의 승인으로 확대하지 마.
- 단순 ‘이어 해’나 파일 수령을 최종 영상의 전체 청취 승인으로 확대하지 마.
- 청취 승인 대기 중 재개할 때는 사용자 피드백과 현재 결과물을 확인하고, 승인된 자산을 임의로 재생성하지 마.
- 승인 후 그림마다 반복 확인을 요구하지 말고 합의한 범위에서 진행해.
- 제작 승인을 품질 검수 면제·새 서비스 사용·업로드 승인으로 확대하지 마.
- ‘이어 해’는 현재 ID·대본 버전·승인 범위·생성·검수 상태를 확인하고 미완료 단계부터 진행해.
- ‘수정해’는 지정 범위와 영향을 받는 결과만 수정하고 기존 이력을 보존해.
- 사용자가 지정한 수정 범위는 다시 승인받지 마. 요청을 넘는 주요 변경이 필요할 때만 구체적인 변경안을 제시해.
- 이후 사용자의 명시적인 범위 변경은 최신 지시로 반영해.

[개별 작품의 승인용 제출물]

A. 인물 조합·선정 이유·중심 사건·제목과 질문·목표·동기·주요 전제·결말·목표 길이.

B. 시작부터 결말·마지막 질문·CTA까지 전체 낭독 대본.

C. 씬별 목표·방해·행동·결과·다음 씬 연결·장소·계획 시간.

D. 컷·이미지·cue·낭독 그룹 연결, 주요 동작·접점의 검수 포인트와 예상 신규·재사용 제작량.

E. 선택 판본·읽은 출처·확인한 능력·창작 설정·미확인 사항·관련 쇼츠와 질문의 연결 여부.

F. 내용 검토 결과·기본 뼈대의 주요 조정 이유·제작 후 실제로 확인해야 할 품질·길이·사용자 청취 승인 단계.

- 검토하는 사용자에게 결말을 숨기지 마.
- 전체 대본을 씬 제목·줄거리 요약·‘이하 전투 진행’으로 대신하지 마.
- 완전한 대본을 파일로 보존하고 읽을 수 있게 제공해.
- 출력 한도가 있으면 완전한 파일과 접근 가능한 링크를 제공하고 핵심 내용을 설명해. 요약만 만들고 전체 대본 작성 완료라고 말하지 마.
- 대본 단계의 시간은 계획·추정이며 실측이 아니야.
- 대본·주요 전제의 제작 승인 전에는 무료·유료와 관계없이 실제 이미지·TTS·최종 영상 생성을 실행하지 마.
- 대본 제출이나 파일 생성만으로 COMPLETE 처리하거나 done으로 옮기지 마.
- 검수용 결과물을 먼저 전달하고, 최종 완료는 사용자 청취 승인을 포함한 해당 제작·검수·전달 기준을 실제로 충족한 뒤 기록해.

16. 이번 시스템 구축 작업의 완료 조건
━━━━━━━━━━━━━━━━━━━━━━━━

이번 요청에서는 다음까지만 수행해.

1) 기존 프로젝트 상태와 실제 구현을 확인해.
2) 필요한 변경 파일을 기존 백업·수정 이력 방식으로 보존해.
3) 위 공용 규칙을 문서·프로필·기획·필요한 코드 연결에 반영해.
4) 특정 인물·대진·질문·의뢰·첫 시범편이 기본값으로 남지 않았는지 확인해.
5) 인물 두 명/한 명/주제만/지정 없음/기존 조건/재개/수정의 처리 기준을 확인해.
6) 실제 생성 호출 없는 fixture·mock·형식 검사로 변경 부분을 확인해.
7) 540~900초 경계, 가로 설정, 가변 장면 연결, 낭독 그룹, 형식별 중복, 롱폼 결말과 기존 쇼츠 동작을 필요한 범위에서 확인해.
   롱폼의 기술 검사·청취 승인 상태 분리, 로컬 모델 비필수 처리, 검수본 선전달, 승인 전 COMPLETE 금지, 승인 버전 연결도 확인해.
   쇼츠 자료 참조·질문 연결·별개 사건의 안내 문구·제목 기준이 공용 규칙에 반영됐는지 확인해.
   이미지 원본·세부·최종 화면 검수, 수정 후 재검수, 해시와 검수 기록 연결, 미검수·미해결 결함의 PASS 금지도 확인해.
8) 실제 변경 파일, 구현 범위, 수행한 검사, 미검증 사항과 향후 호출 방법을 보고해.

- 없는 CLI 옵션을 있다고 가정하지 말고 실제 인터페이스를 확인해.
- 이번 검증에서 실제 작품을 예약하거나 대본·이미지·TTS·최종 영상을 만들지 마. 그림 검수 절차를 시험한다는 이유로 새 이미지를 생성하지 마.
- 무음 모드·구형 프로필·가짜 PASS·존재하지 않는 사용자 청취 승인으로 검사를 통과시키지 마.
- 코드 검증과 실제 9~15분 영상의 통합 검수를 구분해. 실제 영상 검수는 미실시로 남겨.
- ‘앞으로 기억하겠다’는 답변만 하고 끝내지 말고 실제 문서·필요 구현에 반영해.
- 접근 불가 등으로 실제 반영을 못 했다면 무엇을 못 했는지 정확히 보고해.

공용 시스템 반영·검증 결과를 보고한 뒤 종료해.
이후 실제 롱폼 제작 요청이 들어오면 이 규칙으로 인물 선정부터 새 이야기 구성·대본·제작·검수·전달까지 진행해.
