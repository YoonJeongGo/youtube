## 과거 문구의 적용 범위

- 아래쪽 v4 절의 “새 편 기본”, 대표 수식어 시작, A/B 반대 조건, 소개 5~8초와 옛 글자 수는 저장된 v4 편의 호환 기록이다. 신규 v5에는 구체적 질문·같은 사건의 순차 공방·소개 4~6초 참고치·v5 글자 상한을 적용한다.
- v5 기획은 같은 사건의 행동·대응 근거를 기록한다. v4의 `opposed: true`를 v5 검사에 맞추려고 거짓으로 적지 않는다. [자동 기획의 v5 연결](automatic_planning.md#v5-신규-기획-연결-2026-11-18-확정)을 함께 확인한다.
- 옛 긴 CTA와 두 줄 낭독/SRT는 과거 재현용이다. 최신은 댓글 문장만 낭독하고 화면 두 줄을 유지하는 `comment_spoken`이다.
- 옛 프로젝트 하위 완성본/검수대기 경로보다 최신 바탕화면 바로 아래의 해시태그 포함 전체 제목 폴더 지시가 우선한다. 반복 상단 보조 문구도 최신 제거 지시를 따른다.
- 일반적인 “계속 제작” 문구는 전제·대본 승인 경계를 넘지 않는다. Gemini 금지는 유지하며 과거 외부 서비스 승인을 새 전송 승인으로 해석하지 않는다.
- 메두사의 현대 개인 신앙 관련 특정 편 처리나 현대 복싱 선수의 제작 예외는 전역 허용으로 확대하지 않는다. 개별 승인과 공통 금지 기준은 구분한다.

## 남은 숫자·표현의 모호성

- 자산 수: v5 대표 직접 소개는 정사각 대표 2장+세로 장면 7장=실제 9장이다. 별도 소개 호환은 대표 2장+세로 9장=11장이고 화면에는 9종이 나온다. 옛 “대표 제외 신규 8장” 문구와 맞지 않으므로 v5의 실제 사용 목록을 확인한다.
- 수정 한도: AGENTS의 “최초+수정 최대 N회”와 상세 문서의 “최초 후 수정 최대 N회”는 최초 포함 여부가 모호하다. 이 감사는 총 허용 횟수를 새로 정하지 않는다. 현재 카운터·이력·해당 사용자 지시를 대조하고 한도를 확대하거나 초기화하지 않는다.
- 외곽 트림은 과거 절의 story/v3 명명과 최신 구조화 v3/v4/v5 경로 설명에 범위 표현 차이가 있다. v5의 기존 검증 경로 유지와 실제 구현을 확인하며 새 트림 정책을 만들지 않는다.

## 공개 사본과 원본 QA 해시

- 공개 문서의 `<PROJECT_ROOT>`·`<USER_HOME>`은 원래 PC의 경로를 정제한 자리표시자다. 실제 설치 위치나 원본 파일이 그곳에 존재한다는 뜻이 아니다.
- 공개 소스 준비의 원본/공개 사본 해시와 변환 이력은 각각의 바이트를 식별한다. 경로 정제·공개용 설명 추가만으로도 문서 해시가 달라질 수 있다. 이를 원래 영상·음성·그림이 바뀌었다는 증거로 해석하지 않는다.
- 에피소드 QA의 입력·미디어·프레임 해시는 검수 당시 원본을 가리킨다. 정제한 QA 사본을 원본과 바이트가 같은 파일로 취급하거나 사본의 해시를 과거 직접 검수 해시로 바꿔 쓰지 않는다.
- 공개 사본이나 ZIP의 해시 검증은 저장·전송 무결성 검사다. 원본 미디어의 품질 PASS, 음향 확인, 완전 복원 가능성을 대신하지 않는다. 원본과 정제 사본의 대응·누락 범위를 함께 확인한다.
- 로컬 경로로 언급된 planning/backups/episodes의 증거가 공개 checkout에 모두 들어 있는 것은 아니다. 보관 범위는 [아카이브 목록](../archives/catalog.json)과 [공유 시스템 안내](shared_system.md)를 확인한다.

이 문서는 기존 원본·검수 이력·개별 승인 상태를 변경하지 않는다. GitHub 저장만으로 모든 채팅이 최신 내용을 읽었다거나 제작이 승인됐다고 보고하지 않는다.
